# msrcget

Βιβλιοθήκη πολυ-κατοπτρικής αναλογιακής λήψης HTTP/HTTPS με βάση το ασύγχρονο μοντέλο ολοκλήρωσης [compio](https://crates.io/crates/compio), σχεδιασμένη για την άρση των περιορισμών ροής σε μονό κάτοπτρο, της φθοράς δεδομένων ανά τμήμα και της επιβράδυνσης από αργούς κόμβους.

### Μεθοδολογία δοκιμής

Ο κώδικας δοκιμής βρίσκεται στο `examples/bench.rs` (εκτέλεση `cargo run --profile bench --example bench`):

- Προετοιμασία γραμμής βάσης: πριν τη χρονομέτρηση, γίνεται μια αρχική προ-λήψη του αρχείου, επαληθεύεται το μήκος bytes και υπολογίζονται οι τιμές αναφοράς CRC32 για το σύνολο και κάθε τμήμα. Ο στάδης αυτός δεν καταχωρείται στον χρόνο.
- Όρια χρονομέτρησης: Κάθε λύση εκτελείται ανεξάρτητα για 3 συνεχείς κύκλους. Πριν από κάθε κύκλο διαγράφονται το αρχείο εξόδου και το προσωρινό αρχείο `.part`. Η χρονομέτρηση ξεκινάει από την αποστολή του δικτυακού αιτήματος και σταματάει με την ολοκλήρωση της εγγραφής στο δίσκο (τα `cyper`, `reqwest`, `ureq` εκτελούν ρητά `sync_data` για εγγραφή στο δίσκο. Το `msrcget` περιλαμβάνει το σύνολο της διαδικασίας: ανίχνευση απομακρυσμένου μεγέθους, δημιουργία αραιού αρχείου, ταυτόχρονη αναλογιακή λήψη, `sync_data` για εγγραφή στο δίσκο, αποκοπή μεταδεδομένων τέλους και ατομική μετονομασία).
- Επαλήθευση παραγώματος: Μετά τη λήξη της χρονομέτρησης κάθε κύκλου, διαβάζεται ροϊκά το αρχείο στον δίσκο και επαληθεύεται το μήκος bytes και το CRC32 του συνόλου. Η διαδικασία επαλήθευσης δεν καταχωρείται στον χρόνο λήψης.
- Μετατροπή διαπερατότητας: Λαμβάνεται η διάμεση από τους 3 κύκλους χρόνου και υπολογίζεται η διαπερατότητα ως `αριθμός bytes αρχείου / 1048576 / διάμεση δευτερόλεπτα` (`1 MB = 1048576 bytes`).
- Κανόνες ανάθεσης κατοπτρών: Οι πολυ-κατοπτρικές λύσεις (`msrcget`, `down`) λαμβάνουν και τα 5 κατοπτρικά του σεναρίου. Οι μονο-κατοπτρικές λύσεις (`cyper`, `reqwest`, `ureq`) δεν υποστηρίζουν αναλογική πολυ-κατοπτρική λήψη, και το αίτημα κατευθύνεται στο 1ο κάτοπτρο της λίστας.

## Χαρακτηριστικά

- Επαλήθευση ανά τμήμα και εναλλαγή σε περίπτωση βλάβης: Ο κλήτης εισάγει την διεπαφή επαλήθευσης `Verify` για την επαλήθευση κάθε τμήματος. Όταν η επαλήθευση αποτύχει ή το δικτυακό αίτημα αποτύχει, γίνεται αυτόματη εναλλαγή σε άλλο κάτοπτρο που δεν έχει δοκιμαστεί. Αν όλα τα κατοπτρικά αποτύχουν, επιστρέφεται `Error::Exhausted`.
- Αραιά αρχεία και επανάληψη διακοπής: Δημιουργείται εκ των προτέρων ένα αραιό προσωρινό αρχείο `.part` με το συνολικό μέγεθος του αρχείου και τίθεται κλείδωμα αρχείου (σε σύγκρουση κλειδώματος επιστρέφεται `Error::Locked`). Στο τέλος του αρχείου γράφεται διπλό-πηνάρικο bitmap CRC32 για την μόνιμη αποθήκευση των ολοκληρωμένων τμημάτων. Μετά από διακοπή και επανεκκίνηση, η επανάληψη γίνεται αυτόματα. Όταν ολοκληρωθεί, τα μεταδεδομένα του τέλους αποκομίζονται και γίνεται ατομική μετονομασία στο τελικό αρχείο.
- Διχοτομική κλοπή εργασίας: Το κάτοπτρο που ολοκληρώνει πρώτα την περιοχή του διχοτομεί την μεγαλύτερη απομεινάνουσα περιοχή και αναλαμβάνει το δεύτερο μισό, εξισώνοντας το φορτίο των κατοπτρών.
- Ταυτόχρονη σούπερ-ταχύτητα τέλους: Όταν ο αριθμός ελεύθερων κορoutines υπερβαίνει τα απομεινάντα μη ολοκληρωμένα τμήματα, αποστέλλονται επιπλέον αιτήματα σε κατοπτρικά που δεν έχουν δοκιμαστεί για αυτό το τμήμα. Αμέσως μόλις το πρώτο δεδομένο που περνάει την επαλήθευση γραφεί στον δίσκο, τα υπόλοιπα αιτήματα για το ίδιο τμήμα ακυρώνονται.
- Αυτόματος σχεδιασμός τμημάτων: Το μέγεθος τμήματος καθορίζεται βάσει του συνολικού μεγέθους του αρχείου και του αριθμού ταυτόχρονης. Σε επανάληψη υπάρχοντος `.part`, χρησιμοποιείται αυτόματα το καταγεγραμμένο μέγεθος τμήματος.
- Επαναχρησιμοποίηση συνδέσεων και υποστήριξη προτύπων: Ενσωματωμένη δεξαμενή συνδέσεων για επαναχρησιμοποίηση HTTP/1.1 keep-alive στον ίδιο κάτοπτρο. Υποστήριξη αναλογικής μεταφοράς coding, HTTPS ([rustls](https://crates.io/crates/rustls)), ανακατεύθυνσης `301`/`302`/`303`/`307`/`308` δια-διαδρομής και δια-κατοπτρικής, και ελέγχου χρονικού ορίου.

## Παράδειγμα χρήσης

Ο κώδικας παραδείγματος βρίσκεται στο `examples/basic.rs` (εκτέλεση `cargo run --example basic`):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// Επαληθευτής ανά τμήμα βάσει CRC32
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // Κάτοπτρο 0 επιστρέφει φθαρμένα δεδομένα στο 1ο τμήμα, κάτοπτρο 1 γρήγορο κανονικά, κάτοπτρο 2 αργός κόμβος υψηλής καθυστέρησης
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // Προεπιλεγμένη ταυτόχρονη πολυ-κατοπτρική λήψη: αυτόματος σχεδιασμός μεγέθους τμήματος, εγγραφή αραιού .part και μετά αποκοπή-μετονομασία
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // Πολυ-κατοπτρική λήψη με επαλήθευση CRC32 ανά τμήμα: φθαρμένο τμήμα → αυτόματη εναλλαγή κατοπτρικού, γρήγορο κάτοπτρο → αυτόματη κλοπή & ταυτόχρονη σούπερ-ταχύτητα αργού κατοπτρικού
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## Περιγραφές διεπαφής

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

Λήψη του `url_li` στο `path` με προεπιλεγμένο αριθμό ταυτόχρονης `CONC` (`8`) και προεπιλεγμένο χρονικό όριο `TIMEOUT` (`30s`), επιστρέφει το συνολικό μέγεθος bytes του αρχείου.

### `Get`

Είσοδος constructor `Get::new(url_li, path)`, υποστηρίζει διαδοχική διαμόρφωση:

- `.size(size: u64)`: Ρητή καθορισμός γνωστού συνολικού μεγέθους bytes, παράκαμψη ανίχνευσης απομακρυσμένου μεγέθους.
- `.chunk_size(chunk_size: usize)`: Καθορισμός bytes ανά τμήμα (πέρασμα `0` επιστρέφει `Error::ChunkSize`).
- `.conc(conc: usize)`: Καθορισμός αριθμού ταυτόχρονων κορoutines λήψης.
- `.timeout(timeout: Duration)`: Καθορισμός χρονικού ορίου ανά αίτημα και ανάγνωση.
- `.verify<V2: Verify>(verify: V2)`: Εισαγωγή επαληθευτή, ήδη υλοποιημένο για `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` και `Arc<T>`.
- `.run().await`: Εκκίνηση λήψης και επιστροφή `Result<u64>`.

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` είναι ο δείκτης τμήματος με βάση 0, `data` είναι η κοπή bytes του τμήματος, επιστροφή `true` σημαίνει ότι η επαλήθευση πέρασε.

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

Επιστρέφει μέγεθος τμήματος σε δυνάμη του 2 μεταξύ `MIN_CHUNK` (`64 KB`) και `MAX_CHUNK` (`4 MB`).

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

Συνηπενδίδει τη σταθερά κατάληξης `PART_EXT` (`".part"`), επιστρέφει τη διαδρομή του προσωρινού αρχείου επανάληψης.

### `Error` και `Result`

Ενιαίος τύπος επιστροφής `Result<T> = std::result::Result<T, Error>`, οι παραλλαγές του enum σφαλμάτων περιλαμβάνουν: `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`.
