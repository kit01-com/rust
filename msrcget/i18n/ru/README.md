# msrcget

Библиотека многоисточникового блочного HTTP/HTTPS-загрузки на основе асинхронной модели завершения [compio](https://crates.io/crates/compio), предназначенная для решения проблем с ограничением скорости отдельного зеркала, повреждением блочных данных и замедлением из-за медленных узлов

## Оценка производительности

Сравнение пропускной способности загрузки [down](https://crates.io/crates/down), [cyper](https://crates.io/crates/cyper), [reqwest](https://crates.io/crates/reqwest) и [ureq](https://crates.io/crates/ureq) по общедоступным HTTPS-зеркалам:

### Сценарий 1: агрегированная загрузка с нескольких общедоступных зеркал

Загрузка дистрибутива Node.js v22.14.0 (`node-v22.14.0-linux-x64.tar.xz`, 28,5 МБ); порядок зеркал: Tsinghua, USTC, Huawei Cloud, Tencent Cloud, npmmirror (включая межисточническое перенаправление 302)

| Библиотека / Решение | Пропускная способность (МБ/с) |
| --------------------- | ----------: |
| msrcget (5 источников, 8 потоков) |        13.9 |
| msrcget + CRC32       |        13.4 |
| down (5 источников)   |         1.2 |
| cyper (1 источник)    |        14.4 |
| reqwest (1 источник)  |        14.4 |
| ureq (1 источник)     |        14.3 |

### Сценарий 2: смешанная загрузка с быстрыми и медленными источниками

Загрузка пакета заголовочных файлов Node.js v22.14.0 (`node-v22.14.0-headers.tar.gz`, 8,4 МБ); порядок зеркал: Aliyun (ограничение скорости на одно соединение), Tsinghua, Huawei Cloud, Tencent Cloud, официальный сервер Node.js (медленный узел на международном канале)

| Библиотека / Решение | Пропускная способность (МБ/с) |
| --------------------- | ----------: |
| msrcget (5 источников, 8 потоков) |        13.5 |
| msrcget + CRC32       |        13.0 |
| down (5 источников)   |         0.2 |
| cyper (1 источник)    |         6.8 |
| reqwest (1 источник)  |         6.6 |
| ureq (1 источник)     |         6.7 |

### Методика тестирования

Код бенчмарка находится в `examples/bench.rs` (выполнить `cargo run --profile bench --example bench`):

- Подготовка базовой линии: перед замером времени выполняется предварительная загрузка целевого файла, проверка длины в байтах и расчёт базовых значений CRC32 для всего файла и каждого блока; этот этап не учитывается во времени
- Границы замера: каждый вариант запускается 3 раза подряд независимо; перед каждым прогоном удаляются выходной файл и временный файл `.part`; отсчёт времени одного прогона начинается с момента отправки сетевого запроса и останавливается после завершения записи файла на диск (`cyper`, `reqwest`, `ureq` явно выполняют `sync_data` для сброса буферов; `msrcget` включает полный цикл: обнаружение удалённой длины, создание разреженного файла, параллельную загрузку блоков, обрезание хвостовых метаданных, сброс через `sync_data` и атомарное переименование).
- Проверка результата: после остановки таймера в каждом запуске выполняется потоковое чтение записанного файла, проверка длины в байтах и CRC32 всего файла; процесс проверки не учитывается во времени загрузки
- Расчёт пропускной способности: берётся медианное время из 3 запусков, пропускная способность вычисляется по формуле `байты файла / 1048576 / медианное время (с)` (`1 МБ = 1048576 байт`)
- Правила распределения источников: многоисточническим решениям (`msrcget`, `down`) передаются все 5 адресов зеркал из сценария; одноисточнические решения (`cyper`, `reqwest`, `ureq`) не поддерживают многоисточническую блочную загрузку и используют только первый адрес зеркала в списке запросов

## Возможности

- Поблочная проверка и переключение при сбоях: вызывающая сторона передаёт интерфейс `Verify` для проверки каждого блока; при неудачной проверке или сетевой ошибке автоматически переключается на ещё не использованные зеркала; при исчерпании всех источников возвращается `Error::Exhausted`
- Разреженные файлы и возобновление загрузки: на основе общей длины файла предварительно создаётся разреженный временный файл `.part` с файловой блокировкой (при конфликте блокировки возвращается `Error::Locked`); в конце файла добавляется битовая карта, отмечающая завершённые блоки; после прерывания и перезапуска загрузка автоматически возобновляется, по завершении всех блоков хвостовые метаданные обрезаются и файл атомарно переименовывается в целевой.
- Бинарное перехватывание задач: источник, первым завершивший свой интервал, делит пополам оставшийся незавершённый интервал с наибольшим диапазоном и забирает вторую половину, уравновешивая нагрузку между зеркалами
- Гонка за хвостовые блоки: когда число свободных корутин превышает число оставшихся незавершённых блоков, неиспользованным зеркалам, ещё не обращавшимся к данному блоку, отправляются избыточные запросы; первый прошедший проверку блок записывается на диск, после чего остальные запросы к этому блоку отменяются
- Автоматическое планирование блоков: размер блока определяется на основе общей длины файла и числа потоков; при возобновлении загрузки из существующего файла `.part` автоматически используется записанный в нём размер блока
- Повторное использование соединений и поддержка протоколов: встроенный пул соединений для повторного использования длинных соединений HTTP/1.1 того же источника; поддержка блочной кодировки передачи, HTTPS ([rustls](https://crates.io/crates/rustls)), перенаправлений `301`/`302`/`303`/`307`/`308` в пределах и между источниками, а также управление таймаутом

## Пример использования

Пример кода в `examples/basic.rs` (выполнить `cargo run --example basic`):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// Проверочный обработчик блоков на основе CRC32
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // Источник 0 возвращает повреждённые данные для 1-го блока, источник 1 — быстрый и исправный, источник 2 — медленный узел с высокой задержкой
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // Многоисточническая параллельная загрузка по умолчанию: автоматическое планирование размера блока, запись в разрежённый .part с последующим обрезанием и переименованием
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // Многоисточническая загрузка с покомпонентной проверкой CRC32: при повреждённом блоке автоматическое переключение на другой источник, быстрые источники перехватывают задачи и соревнуются с медленными за хвостовые блоки
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## Описание интерфейса

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64> where I: IntoIterator<Item = S>, S: AsRef<str>`

Загружает `url_li` в `path` с использованием значения по умолчанию `CONC` (`8`) и таймаута по умолчанию `TIMEOUT` (`30 секунд`), возвращает общее количество байт файла.

### `Get`

Точка входа билдера `Get::new(url_li, path)`, поддерживает цепочное конфигурирование:

- `.size(size: u64)`: явно задаёт известное общее количество байт файла, пропускает обнаружение удалённой длины (передача `0` означает завершение как пустого файла).
- `.chunk_size(chunk_size: usize)`: задаёт размер блока в байтах (передача `0` возвращает `Error::ChunkSize`)
- `.conc(conc: usize)`: задаёт количество параллельных корутин загрузки (передача `0` трактуется как `1`).
- `.timeout(timeout: Duration)`: задаёт таймаут для одного запроса и чтения
- `.verify<V2: Verify>(verify: V2)`: вставляет проверочный обработчик; реализован для `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` и `Arc<T>`
- `.run().await`: запускает загрузку и возвращает `Result<u64>`

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` — нулевой номер блока, `data` — байтовый срез данного блока; возврат `true` означает успешную проверку

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

Возвращает размер блока в байтах, являющийся степенью двойки, в диапазоне от `MIN_CHUNK` (`64 КБ`) до `MAX_CHUNK` (`4 МБ`)

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

Дополняет путь константой суффикса `PART_EXT` (`.part`); возвращает путь к временному файлу для возобновления загрузки

### `Error` и `Result`

Единый тип возврата `Result<T> = std::result::Result<T, Error>`; варианты перечисления ошибок: `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`
