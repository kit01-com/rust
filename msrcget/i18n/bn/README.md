# msrcget

[compio](https://crates.io/crates/compio) অ্যাসিঙ্ক কমপ্লিশন মডেলে ভিত্তিক মাল্টি-সোর্স চাঙ্কড HTTP/HTTPS ডাউনলোড লাইব্রেরি, যা সিঙ্গেল মিরর রেট-লিমিটেশন, চাঙ্ক ডেটা ক্ষতি এবং ধীর নোড টেইলিং সমস্যা দূর করার উদ্দেশ্যে তৈরি।

## পারফরম্যান্স বেনচমার্ক

[down](https://crates.io/crates/down), [cyper](https://crates.io/crates/cyper), [reqwest](https://crates.io/crates/reqwest) এবং [ureq](https://crates.io/crates/ureq)-এর পাবলিক HTTPS মিরর সোর্সে ডাউনলোড থ্রুপুট তুলনা:

### সিন্যারিও ১: মাল্টি-পাবলিক মিরর অ্যাগ্রিগেশন ডাউনলোড

### পরীক্ষার পদ্ধতি

বেনচমার্ক কোড `examples/bench.rs`-এ অবস্থিত (`cargo run --profile bench --example bench` চালানো হবে):

- বেসলাইন প্রস্তুতি: টাইমিংের আগে লক্ষ্য ফাইলটি একবার প্রি-ডাউনলোড করা হয়, বাইট লম্বা যাচাই করে পুরো প্যাকেজ ও প্রতিটি চাঙ্কের CRC32 রেফারেন্স মান গণনা করা হয়; এই ধাপটি মোট সময়ের মধ্যে গণিত হয় না।
- টাইমিং সীমানা: প্রতিটি স্কিম ৩টি স্বাধীন রাউন্ড ক্রমাগত চালু করা হয়; প্রতিটি রাউন্ড শুরুর আগে আউটপুট ফাইল ও `.part` টেম্পোরারি ফাইল মুছে ফেলা হয়। একটি রাউন্ডের টাইমিং নেটওয়ার্ক রিকোয়েস্ট শুরু থেকে শুরু হয়ে ফাইল ডিস্কে সম্পূর্ণ লেখা পর্যন্ত ধরে নেওয়া হয় (`cyper`, `reqwest`, `ureq` তিনটিই এক্সপ্লিসিট `sync_data` ডিস্ক ফ্লাশ করে; `msrcget`-এর ক্ষেত্রে রিমোট লেংথ প্রসেসিং, স্পার্স ফাইল তৈরি, প্যারালাল চাঙ্কড ডাউনলোড, `sync_data` ডিস্ক ফ্লাশ, টেইল মেটাডেটা ক্রন এবং অ্যাটমিক রিনেম—সব পুরো প্রক্রিয়া অন্তর্ভুক্ত)।
- আউটপুট ভ্যালিডেশন: প্রতিটি রাউন্ডে টাইমিং বন্ধের পর ডিস্কে লেখা ফাইলটি স্ট্রিমিং-রিড করা হয়, ফাইলের বাইট লম্বা ও পুরো প্যাকেজের CRC32 যাচাই করা হয়; ভ্যালিডেশন প্রক্রিয়াটি ডাউনলোড সময়ের মধ্যে গণিত হয় না।
- থ্রুপুট রূপান্তর: ৩ রাউন্ডের সময়ের মধ্যমা নেওয়া হয়, তারপর `ফাইল বাইট / 1048576 / মধ্যমা সেকেন্ড` সূত্রে থ্রুপুট গণনা করা হয় (`1 MB = 1048576 বাইট`)।
- সোর্স বণ্টনের নিয়ম: মাল্টি-সোর্স স্কিম (`msrcget`, `down`) সিন্যারিওর সমস্ত ৫টি মিরর ঠিকানা নেয়; সিঙ্গেল-সোর্স স্কিম (`cyper`, `reqwest`, `ureq`) মাল্টি-সোর্স চাঙ্কিং সাপোর্ট করে না, রিকোয়েস্ট লিস্টের ১ম মিরর ঠিকানা ব্যবহার করে।

## ফিচার

- চাঙ্ক-বাই-চাঙ্ক ভ্যালিডেশন ও ফেইলওভার: কলার `Verify` ইন্টারফেসের মাধ্যমে প্রতিটি চাঙ্ক ভেরিফাই করে; ভেরিফিকেশন ব্যর্থ বা নেটওয়ার্ক রিকোয়েস্ট ফেল হলে অবশিষ্ট অপ্রয়ত মিরর সোর্সে স্বয়ংক্রিয়ভাবে সুইচ করে পুনরায় চেষ্টা করা হয়, সব সোর্স প্রক্রিয়া করেও ব্যর্থ হলে `Error::Exhausted` রিটার্ন হয়।
- স্পার্স ফাইল ও ব্রেকপয়েন্ট রিজুম: ফাইলের মোট লম্বা অনুযায়ী আগাম স্পার্স `.part` টেম্পোরারি ফাইল তৈরি করে ফাইল লক প্রয়োগ করা হয় (লক কনফ্লিক্টে `Error::Locked` রিটার্ন); ফাইলের শেষে ডুয়াল-স্লট পিং-পং CRC32 বিটম্যাপ লেখা হয় যাতে সম্পন্ন চাঙ্ক পার্সিস্ট থাকে, ইন্টারাপ্ট ও রিস্টার্টের পর স্বয়ংক্রিয়ভাবে রিজুম হয়, সব সম্পন্ন হওয়ার পর টেইল মেটাডেটা ক্রন করে অ্যাটমিকভাবে লক্ষ্য ফাইলে রিনেম করা হয়।
- বাইনারি টাস্ক স্টিলিং: নিজের অংশটি প্রথমে সম্পন্ন করা ডাউনলোড সোর্স অবশিষ্ট অবসম্পন্ন সবচেয়ে বড় স্প্যানকে অর্ধেকে বিভক্ত করে দ্বিতীয়ার্ধ গ্রহণ করে, ফলে প্রতিটি মিরর সোর্সের লোড ব্যালান্সড থাকে।
- টেইল মাল্টি-প্যাথ রেসিং: যখন ফ্রি কোরাউটিনের সংখ্যা অবশিষ্ট অবসম্পন্ন চাঙ্কের সংখ্যার চেয়ে বেশি হয়, তখন ঐ চাঙ্ক অপরীক্ষিত মিরর সোর্সে রেডান্ড্যান্ট রিকোয়েস্ট পাঠানো হয়; প্রথম ভ্যালিডেটেড ডেটা ডিস্কে লেখা হওয়ার পর ঐ চাঙ্কের বাকি রিকোয়েস্ট বাতিল করা হয়।
- অটো চাঙ্কিং প্ল্যানিং: ফাইলের মোট লম্বা ও কনকারেন্সি অনুযায়ী চাঙ্ক সাইজ নির্ধারণ করা হয়; বিদ্যমান `.part` ফাইল রিজুম করলে তাতে রেকর্ড করা চাঙ্ক সাইজ স্বয়ংক্রিয়ভাবে ব্যবহার করা হয়।
- কানেকশন রিইউজ ও প্রোটোকল সাপোর্ট: বিল্ট-ইন সেম-সোর্স কানেকশন পুলের মাধ্যমে HTTP/1.1 লং-কানেকশন রিইউজ করা হয়, সাপোর্টেড: চাঙ্কড ট্রান্সফার এনকোডিং, HTTPS ([rustls](https://crates.io/crates/rustls)), `301`/`302`/`303`/`307`/`308` ক্রস-প্যাথ ও ক্রস-সোর্স রিডাইরেক্ট এবং টাইমআউট কন্ট্রোল।

## ব্যবহারের উদাহরণ

উদাহরণ কোড `examples/basic.rs`-এ অবস্থিত (`cargo run --example basic` চালানো হবে):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// CRC32-ভিত্তিক চাঙ্ক-বাই-চাঙ্ক ভেরিফায়ার
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // সোর্স ০-এর ১ম চাঙ্ক ক্ষতিগ্রস্ত ডেটা রিটার্ন করে, সোর্স ১ দ্রুত ও স্বাভাবিক, সোর্স ২ হাই-লেটেন্সি ধীর নোড
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // ডিফল্ট মাল্টি-সোর্স কনকারেন্ট ডাউনলোড: অটো চাঙ্ক সাইজ প্ল্যানিং, স্পার্স .part লেখার পর ক্রন ও রিনেম
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // চাঙ্ক-বাই-চাঙ্ক CRC32 ভেরিফিকেশনসহ মাল্টি-সোর্স ডাউনলোড: ক্ষতিগ্রস্ত চাঙ্কে স্বয়ংক্রিয় সোর্স সুইচ, দ্রুত সোর্স অটো স্টিল ও টেইল রেসিংয়ে ধীর সোর্সের সাথে প্রতিযোগিতা
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## API ডকুমেন্টেশন

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

ডিফল্ট কনকারেন্সি `CONC` (`8`) এবং ডিফল্ট সিঙ্গেল-রিকোয়েস্ট টাইমআউট `TIMEOUT` (`30s`) ব্যবহার করে `url_li` থেকে `path`-এ ডাউনলোড করে, ফাইলের মোট বাইট সংখ্যা রিটার্ন করে।

### `Get`

বিল্ডার এন্ট্রিপয়েন্ট `Get::new(url_li, path)`, চেইনড কনফিগারেশন সাপোর্ট করে:

- `.size(size: u64)`: পরিচিত ফাইলের মোট বাইট সংখ্যা এক্সপ্লিসিটভাবে নির্ধারণ, রিমোট লেংথ প্রসেসিং স্কিপ করে।
- `.chunk_size(chunk_size: usize)`: সিঙ্গেল চাঙ্কের বাইট সংখ্যা নির্ধারণ (`0` দিলে `Error::ChunkSize` রিটার্ন)।
- `.conc(conc: usize)`: কনকারেন্ট ডাউনলোড কোরাউটিন সংখ্যা নির্ধারণ।
- `.timeout(timeout: Duration)`: সিঙ্গেল রিকোয়েস্ট ও রিড টাইমআউট নির্ধারণ।
- `.verify<V2: Verify>(verify: V2)`: ভেরিফায়ার ইনজেক্ট; `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` এবং `Arc<T>`-এ ইমপ্লিমেন্টেড।
- `.run().await`: ডাউনলোড শুরু করে এবং `Result<u64>` রিটার্ন করে।

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` হল ০-ভিত্তিক চাঙ্ক ইনডেক্স, `data` ঐ চাঙ্কের বাইট স্লাইস, `true` রিটার্ন মানে ভেরিফিকেশন সফল।

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

`MIN_CHUNK` (`64 KB`) ও `MAX_CHUNK` (`4 MB`) এর মধ্যে ২-এর ঘাত চাঙ্ক বাইট সংখ্যা রিটার্ন করে।

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

সফিক্স কনস্ট্যান্ট `PART_EXT` (`".part"`) অ্যাপেন্ড করে রিজুম টেম্পোরারি ফাইলের পথ রিটার্ন করে।

### `Error` ও `Result`

ইউনিফাইড রিটার্ন টাইপ `Result<T> = std::result::Result<T, Error>`, এরর এনামের ভ্যারিয়েন্ট: `EmptySrc`、`ChunkSize`、`Url`、`Scheme`、`Io`、`Tls`、`Timeout`、`Redirect`、`Status`、`Proto`、`Probe`、`Locked`、`Exhausted { idx }`।
