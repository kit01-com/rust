# msrcget

[compio](https://crates.io/crates/compio) ಏಸಿಂಕ್ ಕಂಪ್ಲೆಷನ್ ಮಾದರಿಯ ಆಧಾರದ ಬಹು-ಮೂಲ ಚೂನ್ಕ್ಡ್ HTTP/HTTPS ಡೌನ್‌ಲೋಡ್ ಲೈಬ್ರೆರಿ, ಏಕ ಮಿರರ್ ರೇಟ್ ಲಿಮಿಟಿಂಗ್, ಚೂನ್ಕ್ ದತ್ತಾಂಶ ಹಾಳೆಗೆಡುವಿಕೆ ಮತ್ತು ನಿಧಾನ ನೋಡ್ ಟೇಲ್ ಸಮಸ್ಯೆಗಳನ್ನು ಪರಿಹರಿಸಲು ಬಳಸಲಾಗುತ್ತದೆ.

## ಪ್ರದರ್ಶನ ಮಾಪನ

[down](https://crates.io/crates/down), [cyper](https://crates.io/crates/cyper), [reqwest](https://crates.io/crates/reqwest) ಮತ್ತು [ureq](https://crates.io/crates/ureq) ಗಳ ಸಾರ್ವಜನಿಕ HTTPS ಮಿರರ್ ಮೂಲಗಳಲ್ಲಿನ ಡೌನ್‌ಲೋಡ್ ಥ್ರೂಪುಟ್ ಹೋಲಿಕೆ:

### ಸನ್ನಿವೇಶ 1: ಬಹು ಸಾರ್ವಜನಿಕ ಮಿರರ್ ಅಗ್ರೆಗೇಟೆಡ್ ಡೌನ್‌ಲೋಡ್

Node.js v22.14.0 ವಿತರಣಾ ಪ್ಯಾಕೇಜ್ ಡೌನ್‌ಲೋಡ್ (`node-v22.14.0-linux-x64.tar.xz`, 28.5 MB), ಮಿರರ್ ಕ್ರಮ: ಟಿಂಗ್‌ಹುವಾ, USTC, ಹುವಾಯ್ ಕ್ಲೌಡ್, ಟೆಂಸೆಂಟ್ ಕ್ಲೌಡ್, npmmirror (302 ಕ್ರಾಸ್-ಮೂಲ ರೆಡೈರೆಕ್ಟ್ ಒಳಗೊಂಡಿದೆ).

| ಲೈಬ್ರೆರಿ / ಪರಿಹಾರ | ಥ್ರೂಪುಟ್ (MB/s) |
| --- | ---: |
| msrcget (5 ಮೂಲ, 8 ಸಮಾನಾಂತರ) | 13.9 |
| msrcget + CRC32 | 13.4 |
| down (5 ಮೂಲ) | 1.2 |
| cyper (ಏಕ ಮೂಲ) | 14.4 |
| reqwest (ಏಕ ಮೂಲ) | 14.4 |
| ureq (ಏಕ ಮೂಲ) | 14.3 |

### ಸನ್ನಿವೇಶ 2: ವೇಗ-ನಿಧಾನ ಮೂಲ ಮಿಕ್ಸ್ಡ್ ಡೌನ್‌ಲೋಡ್

Node.js v22.14.0 ಫೈಲ್‌ಹೆಡರ್ ಪ್ಯಾಕೇಜ್ ಡೌನ್‌ಲೋಡ್ (`node-v22.14.0-headers.tar.gz`, 8.4 MB), ಮಿರರ್ ಕ್ರಮ: ಅಲಿಬಾಬಾ ಕ್ಲೌಡ್ (ಏಕ ಕನೆಕ್ಷನ್ ರೇಟ್ ಲಿಮಿಟ್), ಟಿಂಗ್‌ಹುವಾ, ಹುವಾಯ್ ಕ್ಲೌಡ್, ಟೆಂಸೆಂಟ್ ಕ್ಲೌಡ್, Node.js ಅಧಿಕೃತ ಮೂಲ (ಕ್ರಾಸ್-ಬೋರ್ಡರ್ ನಿಧಾನ ನೋಡ್).

| ಲೈಬ್ರೆರಿ / ಪರಿಹಾರ | ಥ್ರೂಪುಟ್ (MB/s) |
| --- | ---: |
| msrcget (5 ಮೂಲ, 8 ಸಮಾನಾಂತರ) | 13.5 |
| msrcget + CRC32 | 13.0 |
| down (5 ಮೂಲ) | 0.2 |
| cyper (ಏಕ ಮೂಲ) | 6.8 |
| reqwest (ಏಕ ಮೂಲ) | 6.6 |
| ureq (ಏಕ ಮೂಲ) | 6.7 |

### ಪರೀಕ್ಷಾ ವಿಧಾನ

ಬೆಂಚ್‌ಮಾರ್ಕ್ ಕೋಡ್ `examples/bench.rs`-ನಲ್ಲಿದೆ (`cargo run --profile bench --example bench` ರನ್ ಮಾಡಿ):

- ಮೂಲ ಆಯತ: ಸಮಯ ಗುರುತಿಸುವಿಕೆಗೆ ಮೊದಲು ಗುರಿ ಫೈಲ್‌ವನ್ನು ಒಮ್ಮೆ ಮೊದಲ-ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ, ಬೈಟ್ ಉದ್ದ ಪರಿಶೀಲಿಸಿ ಮತ್ತು ಪೂರ್ಣ ಪ್ಯಾಕೇಜ್ ಹಾಗೂ ಪ್ರತಿ ಚೂನ್ಕ್‌ನ CRC32 ಪ್ರಮಾಣ ಮೌಲ್ಯ ಲೆಕ್ಕಾಚಾರ ಮಾಡಿ, ಈ ಹಂತವನ್ನು ಸಮಯದಲ್ಲಿ ಸೇರಿಸಲಾಗುವುದಿಲ್ಲ.
- ಸಮಯ ಗಡಿ: ಪ್ರತಿ ಪರಿಹಾರ 3 ಸ್ವತಂತ್ರ ಸುತ್ತುಗಳಲ್ಲಿ ಅನುಕ್ರಮವಾಗಿ ರನ್ ಮಾಡಲಾಗುತ್ತದೆ, ಪ್ರತಿ ಸುತ್ತು ಪ್ರಾರಂಭವಾಗುವ ಮೊದಲು ಔಟ್‌ಪುಟ್ ಫೈಲ್ ಮತ್ತು `.part` ತಾತ್ಕಾಲಿಕ ಫೈಲ್ ಅನ್ನು ತೆಗೆದುಹಾಕಲಾಗುತ್ತದೆ; ಏಕ ಸುತ್ತು ನೆಟ್‌ವರ್ಕ್ ವಿನಂತಿ ಪ್ರಾರಂಭಿಸುವ ಸಮಯದಿಂದ ಪ್ರಾರಂಭಿಸಿ, ಫೈಲ್ ಡಿಸ್ಕ್‌ಗೆ ಬರೆಯಲ್ಪಟ್ಟಾಗ ಸಮಯ ನಿಲ್ಲಿಸಲಾಗುತ್ತದೆ (`cyper`, `reqwest`, `ureq` ಎಲ್ಲವೂ ಸ್ಪಷ್ಟವಾಗಿ `sync_data` ಫ್ಲಶ್ ಮಾಡುತ್ತವೆ; `msrcget` ದೂರ ಉದ್ದ ಪ್ರೋಬ್, ಸ್ಪಾರ್ಸ್ ಫೈಲ್ ರಚನೆ, ಸಮಾನಾಂತರ ಚೂನ್ಕ್ ಡೌನ್‌ಲೋಡ್, `sync_data` ಫ್ಲಶ್, ಕೊನೆಯ ಮೆಟಾಡೇಟಾ ಕಡಿತ ಮತ್ತು ಅಟಾಮಿಕ್ ಹೆಸರಿನ ಬದಲಾವಣೆಯ ಮೂಲಸಂಪೂರ್ಣ ಪ್ರಕ್ರಿಯೆಯನ್ನು ಒಳಗೊಂಡಿದೆ).
- ಉತ್ಪನ್ನ ಪರಿಶೀಲನೆ: ಪ್ರತಿ ಸುತ್ತು ಸಮಯ ನಿಲ್ಲಿಸಿದ ನಂತರ ಸ್ಟ್ರೀಮ್ ಓದು ಮೂಲಕ ಡಿಸ್ಕ್ ಫೈಲ್ ಓದಿ, ಫೈಲ್ ಬೈಟ್ ಉದ್ದ ಮತ್ತು ಪೂರ್ಣ ಪ್ಯಾಕೇಜ್ CRC32 ಪರಿಶೀಲಿಸಿ, ಪರಿಶೀಲನೆ ಪ್ರಕ್ರಿಯೆಯನ್ನು ಡೌನ್‌ಲೋಡ್ ಸಮಯಕ್ಕೆ ಸೇರಿಸಲಾಗುವುದಿಲ್ಲ.
- ಥ್ರೂಪುಟ್ ಪರಿವರ್ತನೆ: 3 ಸುತ್ತುಗಳ ಮಧ್ಯಮ ಮೌಲ್ಯವನ್ನು ತೆಗೆದುಕೊಂಡು, `ಫೈಲ್ ಬೈಟ್‌ಗಳು / 1048576 / ಮಧ್ಯಮ ಸೆಕೆಂಡ್‌ಗಳು` ಮೂಲಕ ಥ್ರೂಪುಟ್ ಲೆಕ್ಕಾಚಾರ ಮಾಡಲಾಗುತ್ತದೆ (`1 MB = 1048576 ಬೈಟ್‌ಗಳು`).
- ಮೂಲ ಅನುಬಂಧನ ನಿಯಮ: ಬಹು-ಮೂಲ ಪರಿಹಾರಗಳು (`msrcget`, `down`) ಸನ್ನಿವೇಶದ ಎಲ್ಲಾ 5 ಮಿರರ್ ವಿಳಾಸಗಳನ್ನು ನೀಡುತ್ತವೆ; ಏಕ-ಮೂಲ ಪರಿಹಾರಗಳು (`cyper`, `reqwest`, `ureq`) ಬಹು-ಮೂಲ ಚೂನ್ಕ್ಡ್ ಬೆಂಬಲಿಸುವುದಿಲ್ಲ, ವಿನಂತಿ ಪಟ್ಟಿಯ ಮೊದಲ ಮಿರರ್ ವಿಳಾಸವನ್ನು ಒಳಗೊಳ್ಳುತ್ತವೆ.

## ಲಕ್ಷಣಗಳು

- ಚೂನ್ಕ್-ದವರ ಪರಿಶೀಲನೆ ಮತ್ತು ಫೋಲ್ಟ್ ಸ್ವಿಚಿಂಗ್: ಕಾಲ್ ಮಾಡುವವರು `Verify` ಪರಿಶೀಲನೆ ಇಂಟರ್‌ಫೇಸ್ ನೀಡಿ ಪ್ರತಿ ಚೂನ್ಕ್‌ವನ್ನು ಪರಿಶೀಲಿಸುತ್ತಾರೆ; ಪರಿಶೀಲನೆ ವಿಫಲವಾದಾಗ ಅಥವಾ ನೆಟ್‌ವರ್ಕ್ ವಿನಂತಿ ವಿಫಲವಾದಾಗ, ಸ್ವಯಂಪ್ರವರ್ತನೆಯಾಗಿ ಪ್ರಯತ್ನಿಸದ ಉಳಿದ ಮಿರರ್ ಮೂಲಕ್ಕೆ ಬದಲಾಯಿಸಿ ಮರುಪ್ರಯತ್ನಿಸುತ್ತದೆ, ಎಲ್ಲಾ ಮೂಲಗಳೂ ವಿಫಲವಾದಾಗ `Error::Exhausted` ಹಿಂತಿರುಗಿಸುತ್ತದೆ.
- ಸ್ಪಾರ್ಸ್ ಫೈಲ್ ಮತ್ತು ಬ್ರೇಕ್‌ಪಾಯಿಂಟ್ ರಿಸ್ಯೂಮ್: ಫೈಲ್ ಒಟ್ಟು ಉದ್ದದ ಆಧಾರದ ಮೇಲೆ ಸ್ಪಾರ್ಸ್ `.part` ತಾತ್ಕಾಲಿಕ ಫೈಲ್ ಮೊದಲೇ ರಚಿಸಿ ಫೈಲ್ ಲಾಕ್ ಜೋಡಿಸಲಾಗುತ್ತದೆ (ಲಾಕ್ ಕದಡಿ `Error::Locked` ಹಿಂತಿರುಗಿಸುತ್ತದೆ); ಫೈಲ್ ಕೊನೆಯಲ್ಲಿ ಡಬಲ್-ಸಲಾಟ್ ಪಿಂಗ್‌ಪಾಂಗ್ CRC32 ಬಿಟ್‌ಮ್ಯಾಪ್ ಬರೆದು ಪೂರ್ಣಗೊಂಡ ಚೂನ್ಕ್‌ಗಳನ್ನು ನಿರಂತರಗೊಳಿಸಲಾಗುತ್ತದೆ, ಮಧ್ಯದಲ್ಲಿ ನಿಂತ ನಂತರ ಸ್ವಯಂ ರಿಸ್ಯೂಮ್ ಮಾಡುತ್ತದೆ, ಎಲ್ಲಾ ಪೂರ್ಣಗೊಂಡ ನಂತರ ಕೊನೆಯ ಮೆಟಾಡೇಟಾ ಕಡಿತ ಮಾಡಿ ಅಟಾಮಿಕ್ ಆಗಿ ಗುರಿ ಫೈಲ್‌ಗೆ ಹೆಸರಿಸಲಾಗುತ್ತದೆ.
- ಫೈವರ್-ಬಿಂಗ್ ತಾಸಕ್ ಅಪಹರಣ: ಮೊದಲು ತನ್ನ ವಲಯದ ಡೌನ್‌ಲೋಡ್ ಪೂರ್ಣಗೊಳಿಸಿದ ಮೂಲವು ಉಳಿದ ಅಸಮಾಪ್ತ ವ್ಯಾಪ್ತಿಯಲ್ಲಿ ಅತ್ಯಧಿಕದಿಂದ ಅರ್ಧ-ಅರ್ಧವಾಗಿ ಕತ್ತರಿಸಿ ಹಿಂದಿನ ಅರ್ಧವನ್ನು ವಹಿಸಿಕೊಳ್ಳುತ್ತದೆ, ಪ್ರತಿ ಮಿರರ್ ಮೂಲದ ಲೋಡ್ ಸಮತೋಲನ ಕಂಡುಹಿಡಿಯುತ್ತದೆ.
- ಕೊನೆಯ ಚೂನ್ಕ್‌ಗಳ ಮಲ್ಟಿ-ಪಥ್ ಸ್ಪರ್ಧೆ: ಖಾಲಿ ಕೋರೂಟೈನ್‌ಗಳ ಸಂಖ್ಯೆ ಉಳಿದ ಅಸಮಾಪ್ತ ಚೂನ್ಕ್‌ಗಳ ಸಂಖ್ಯೆಗಿಂತ ಹೆಚ್ಚಿರುವಾಗ, ಆ ಚೂನ್ಕ್ ಅನ್ನು ಇನ್ನೂ ಪ್ರಯತ್ನಿಸದ ಮಿರರ್ ಮೂಲಗಳಿಗೆ ಹೆಚ್ಚುವರಿ ವಿನಂತಿಗಳನ್ನು ಕಳುಹಿಸಲಾಗುತ್ತದೆ; ಮೊದಲು ಪರಿಶೀಲನೆ ಮೂಲಕದ ದತ್ತಾಂಶ ಡಿಸ್ಕ್‌ಗೆ ಬರೆಯಲ್ಪಟ್ಟ ತಕ್ಷಣ ಅದೇ ಚೂನ್ಕ್‌ನ ಉಳಿದ ವಿನಂತಿಗಳನ್ನು ರದ್ದುಗೊಳಿಸಲಾಗುತ್ತದೆ.
- ಸ್ವಯಂ ಚೂನ್ಕ್ ಯೋಜನಾಕರಣೆ: ಫೈಲ್ ಒಟ್ಟು ಉದ್ದ ಮತ್ತು ಸಮಾನಾಂತರ ಸಂಖ್ಯೆಯ ಆಧಾರದ ಮೂಲಕ ಚೂನ್ಕ್ ಗಾತ್ರ ಯೋಜಿಸಲಾಗುತ್ತದೆ; ಅಸ್ತಿತ್ವದ `.part` ಫೈಲ್ ರಿಸ್ಯೂಮ್ ಮಾಡುವಾಗ ಅದರಲ್ಲಿ ದಾಖಲಿಸಲಾದ ಚೂನ್ಕ್ ಗಾತ್ರವನ್ನು ಸ್ವಯಂ ಅನುಸರಿಸುತ್ತದೆ.
- ಕನೆಕ್ಷನ್ ಪುನಃಬಳಕೆ ಮತ್ತು ಪ್ರೋಟೋಕಾಲ್ ಬೆಂಬಲ: ಒಳಗಿನ ಏಕ-ಮೂಲ ಕನೆಕ್ಷನ್ ಪೂಲ್ ಮೂಲಕ HTTP/1.1 ಲಾಂಗ್ ಕನೆಕ್ಷನ್ ಪುನಃಬಳಕೆ, ಚೂನ್ಕ್ಡ್ ಟ್ರಾನ್ಸ್‌ಫರ್ ಕೋಡಿಂಗ್, HTTPS ([rustls](https://crates.io/crates/rustls)), `301`/`302`/`303`/`307`/`308` ಕ್ರಾಸ್-ಪಾತ್ ಮತ್ತು ಕ್ರಾಸ್-ಮೂಲ ರೆಡೈರೆಕ್ಟ್ ಹಾಗೂ ಟೈಮ್‌ಔಟ್ ನಿಯಂತ್ರಣ ಬೆಂಬಲಿಸುತ್ತದೆ.

## ಬಳಕೆ ಪ್ರದರ್ಶನ

ಉದಾಹರಣೆ ಕೋಡ್ `examples/basic.rs`-ನಲ್ಲಿದೆ (`cargo run --example basic` ರನ್ ಮಾಡಿ):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// CRC32 ಆಧಾರಿತ ಚೂನ್ಕ್-ದವರ ವೆರಿಫಿಕರ್
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // ಮೂಲ 0 ಮೊದಲ ಚೂನ್ಕ್ ಹಾಳೆಗೆದ ದತ್ತಾಂಶ ಹಿಂತಿರುಗಿಸುತ್ತದೆ, ಮೂಲ 1 ವೇಗದ ಸಾಮಾನ್ಯ, ಮೂಲ 2 ಹೆಚ್ಚು ಲೇಟೆನ್ಸ್ ನಿಧಾನ ನೋಡ್
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // ಅಡಿಪಾಯದ ಬಹು-ಮೂಲ ಸಮಾನಾಂತರ ಡೌನ್‌ಲೋಡ್: ಸ್ವಯಂ ಚೂನ್ಕ್ ಗಾತ್ರ ಯೋಜಿಸು, ಸ್ಪಾರ್ಸ್ .part ಬರೆದು ಕಡಿತ-ಹೆಸರಿನ ಬದಲಾವಣೆ
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // ಚೂನ್ಕ್-ದವರ CRC32 ವೆರಿಫಿಕೇಷನ್ ಜೊತೆ ಬಹು-ಮೂಲ ಡೌನ್‌ಲೋಡ್: ಹುಳುಗ ಚೂನ್ಕ್‌ಗಳಿಗೆ ಸ್ವಯಂ ಮೂಲ ಬದಲಾವಣೆ, ವೇಗದ ಮೂಲ ಸ್ವಯಂ ತಾಸಕ್-ಅಪಹರಣ ಮತ್ತು ಕೊನೆಯ ಚೂನ್ಕ್‌ಗಳಲ್ಲಿ ನಿಧಾನ ಮೂಲಕ್ಕೆ ಸ್ಪರ್ಧೆ
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## ಏಪಿ ದಾಖಲೆ

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

ಅಡಿಪಾಯದ ಸಮಾನಾಂತರ ಸಂಖ್ಯೆ `CONC` (`8`) ಮತ್ತು ಅಡಿಪಾಯದ ಏಕ-ಸಮಯ ಟೈಮ್‌ಔಟ್ `TIMEOUT` (`30s`) ಬಳಸಿ `url_li` ನಿಂದ `path` ಗೆ ಡೌನ್‌ಲೋಡ್ ಮಾಡಿ, ಫೈಲ್ ಒಟ್ಟು ಬೈಟ್ ಸಂಖ್ಯೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### `Get`

ಬಿಲ್ಡರ್ ಪ್ರವೇಶ `Get::new(url_li, path)`, ಸರಪಳಿ ಕಾನ್ಫಿಗುರೇಷನ್ ಬೆಂಬಲ:

- `.size(size: u64)`: ಗುರುತಿಸಿದ ಫೈಲ್ ಒಟ್ಟು ಬೈಟ್ ಸಂಖ್ಯೆ ಸ್ಪಷ್ಟವಾಗಿ ನೀಡಿ, ದೂರ ಉದ್ದ ಪ್ರೋಬ್ ಅನ್ನು ಮೀರಿಹೋಗಿ.
- `.chunk_size(chunk_size: usize)`: ಏಕ ಚೂನ್ಕ್ ಬೈಟ್ ಸಂಖ್ಯೆ ನಿರ್ಧರಿಸಿ (`0` ನೀಡಿದರೆ `Error::ChunkSize` ಹಿಂತಿರುಗಿಸುತ್ತದೆ).
- `.conc(conc: usize)`: ಸಮಾನಾಂತರ ಡೌನ್‌ಲೋಡ್ ಕೋರೂಟೈನ್ ಸಂಖ್ಯೆ ನಿರ್ಧರಿಸಿ.
- `.timeout(timeout: Duration)`: ಏಕ-ವಿನಂತಿ ಮತ್ತು ಓದು ಟೈಮ್‌ಔಟ್ ನಿರ್ಧರಿಸಿ.
- `.verify<V2: Verify>(verify: V2)`: ವೆರಿಫಿಕರ್ ನಲ್ಲಿ ಜೋಡಿಸಿ, ಈಗಾಗಲೇ `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` ಮತ್ತು `Arc<T>` ಗೆ ರಿಲ್ಮ್‌ಫಲಿಸಲಾಗಿದೆ.
- `.run().await`: ಡೌನ್‌ಲೋಡ್ ಪ್ರಾರಂಭಿಸಿ `Result<u64>` ಹಿಂತಿರುಗಿಸಿ.

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` 0-ಆಧಾರಿತ ಚೂನ್ಕ್ ಸಂಖ್ಯೆ, `data` ಆ ಚೂನ್ಕ್‌ನ ಬೈಟ್ ಸ್ಲೈಸ್, `true` ಹಿಂತಿರುಗಿಸಿದರೆ ಪರಿಶೀಲನೆ ಯಶಸ್ವಿ.

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

`MIN_CHUNK` (`64 KB`) ಮತ್ತು `MAX_CHUNK` (`4 MB`) ನಡುವೆ 2-ನಿ ಕ್ಷಮೆ ಚೂನ್ಕ್ ಬೈಟ್ ಸಂಖ್ಯೆ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

ಸರ್ಫಿಕ್ಸ್ ಸ್ಥಿರಾಂಕ `PART_EXT` (`".part"`) ಜೋಡಿಸಿ, ರಿಸ್ಯೂಮ್ ತಾತ್ಕಾಲಿಕ ಫೈಲ್ ಪಾತ್ ಹಿಂತಿರುಗಿಸುತ್ತದೆ.

### `Error` ಮತ್ತು `Result`

ಸಮನ್ವಯ ಫಲಿತಾಂಶ ರೀತಿ `Result<T> = std::result::Result<T, Error>`, ಎರರ್ ಎನಂ ನಿಯೋಜನಾ ರೂಪಗಳು: `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`.
