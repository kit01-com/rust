# msrcget

[compio](https://crates.io/crates/compio) асинхрондуу аяктоо моделине негизделген көп булактык тилкеленген HTTP/HTTPS жүктүү китепханасы; бир гана айналымга ылдамдык чектөөсү, тилкеленген маалыматтын бузулушу жана жай түйүндөрдүн артка калышы маселелерин чечүү үчүн колдонулат.

## Перформанс баалоосу

[down](https://crates.io/crates/down), [cyper](https://crates.io/crates/cyper), [reqwest](https://crates.io/crates/reqwest) жана [ureq](https://crates.io/crates/ureq) китепканаларын коомдук HTTPS айналым булактарындагы жүктүү пропуск жөндөмү боюнча салыштыруу:

### Сценарий 1: Көп коомдук айналымдарды бириктирүү менен жүктүү

Node.js v22.14.0 бөлүп чыгарылган пакетин жүктөө (`node-v22.14.0-linux-x64.tar.xz`, 28.5 MB); айналымдар ирет менен: Tsinghua, USTC, Huawei Cloud, Tencent Cloud, npmmirror (302 булак аркылуу кайра багыттоо менен).

| Китепкана / ыраатташтыруу | Пропуск жөндөмү (MB/с) |
| --- | ---: |
| msrcget (5 булак, 8 параллел) | 13.9 |
| msrcget + CRC32 | 13.4 |
| down (5 булак) | 1.2 |
| cyper (бир булак) | 14.4 |
| reqwest (бир булак) | 14.4 |
| ureq (бир булак) | 14.3 |

### Сценарий 2: Жылдык жана жай булактардын аралашмасы менен жүктүү

Node.js v22.14.0 колдонмолуу пакетин жүктөө (`node-v22.14.0-headers.tar.gz`, 8.4 MB); айналымдар ирет менен: Alibaba Cloud (бир байланышка ылдамдык чектөөсү), Tsinghua, Huawei Cloud, Tencent Cloud, Node.js расмий булагы (чегара аркылуу жай түйүн).

| Китепкана / ыраатташтыруу | Пропуск жөндөмү (MB/с) |

### Сыноо ыкмасы

Баалоо коду `examples/bench.rs` файлында жайгашкан (`cargo run --profile bench --example bench` аткарылат):

- База даярдоо: Убакыт өлчөөдөн мурун максаттуу файлды бир жолу алдын ала жүктөп, байт узундугун текшерүү жана толук пакеттин жана ар бир тилкенин CRC32 базалык маанисин эсептөө; бул этап убакытка киргизилбейт.
- Убакыт чектери: Ар бир ыраатташтыруу 3 жолу өзүнчө иштетилет, ар бир жолунун башында чыгуу файлы жана `.part` убактылуу файл жок кылынат; бир жол сетворк буйругунун башынан башталып, файл дискке жазылып бүткөнчө убакыт өлчөнөт (`cyper`, `reqwest`, `ureq` ар бири ачык түрдө `sync_data` дискке жазууну аткарат; `msrcget` алыскы узундукту өздөштүрүү, сирек файл түзүү, параллел тилкеленген жүктүү, `sync_data` дискке жазуу, жыйынтык метаданелерди кесүү жана атомдуу атын өзгөртүү толук процесин камтыйт).
- Натыйжаны текшерүү: Ар бир жолдун убакытын токтоткондон кийин дисктеги файлды агымдуу окуп, файлдын байт узундугун жана толук пакеттин CRC32сын текшерүү; текшерүү жүктүү убактысына киргизилбейт.
- Пропуск жөндөмүн эсептөө: 3 жолдун орточо (медиана) убакытын алып, `файлдын байт саны / 1048576 / медиана секунд` формуласы боюнча пропуск жөндөмүн эсептөө (`1 MB = 1048576 байт`).
- Булак бөлүштүрүү эрежеси: Көп булактык ыраатташтырууларга (`msrcget`, `down`) сценарийдеги бардык 5 айналым дарегин өткөрүлөт; бир булактык ыраатташтыруулар (`cyper`, `reqwest`, `ureq`) көп булактык тилкеленген жүктүүнү колдобойт, суроо тизмесинин 1-айналым дарегин колдонот.

## Өзгөчөлүктөр

- Тилкеленген текшерүү жана бузулганда алмаштыруу: Колдонуучу `Verify` текшерүү интерфейс аркылуу ар бир тилкени текшерет; текшерүү өтпөсө же сетворк буйругу иштебесе, автоматтык түрдө азырынча колдонбөгөн калган айналым булактарына өтүп кайра аракет кылат, бардык булактарды үчүңдөй дагы иштебесе `Error::Exhausted` кайтарат.
- Сирек файл жана үзгүлтүктөн улантуу: Файлдын жалпы узундугу боюнча алдын ала сирек `.part` убактылуу файл түзүлүп файл блокировкасы коюлат (блокировка кагылышы `Error::Locked` кайтарат); файлдын жыйында эки слоттук пинг-понг CRC32 битмаасы менен бүткөн тилкелер сакталат, үзгүлтүктөн кийин автоматтык түрдө улантат, толук бүткөндө жыйынтык метаданелерин кесип атын атомдуу өзгөртөт.
- Экиге бөлүп тапшырууну жулуп алуу: Өз аралыгынын жүктүүсүн биринчи бүтүргөн булак калган бүткөн эң чоң аралыктан экиге бөлүп экинчи жармын кабыл алат, ар бир айналым булагына жүктү теңдештирет.
- Тартылуудагы көп жолдуу шайкештик: Бош корутсулардын саны калган бүткөн тилкелердин санынан көп болгондо, ошол тилкени азырынча колдонбогон айналым булактарына артыкча буйруктар жөнөтүлөт; биринчи жолу өткөн маалымат дискке жазылып бүткөн сайын ошол тилкенин калган буйруктары дароо токтотулат.
- Автоматтык тилкеленүү пландоо: Файлдын жалпы узундугу жана параллелдүүлүк саны боюнча тилке өлчөмүн пландоо; бар болгон `.part` файлын улантканда анын ичиндеги жазылган тилке өлчөмүн автоматтык түрдө колдонот.
- Байланышты кайра колдонуу жана протокол колдоосу: Ошол эле булак үчүн HTTP/1.1 узун байланыштардын пулу ичинде кайра колдонулат, тилкеленген берүү коддоосун, HTTPS ([rustls](https://crates.io/crates/rustls)), `301`/`302`/`303`/`307`/`308` жол аркылуу жана булак аркылуу кайра багыттоолорду жана убакыт чектөөнү колдойт.

## Колдонуу демонстрациясы

Мисал коду `examples/basic.rs` файлында жайгашкан (`cargo run --example basic` аткарылат):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// CRC32 негизиндеги тилкеленген текшерүүчү
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // Булак 0 биринчи тилкени бузулган маалымат кайтарат, булак 1 жогорку ылдамдыкта кабарат, булак 2 жогорку кечикүү жай түйүн
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // Өткүр көп булактык параллел жүктүү: тилке өлчөмүн автоматтык пландоо, сирек .part жазып жыйынын кесип атын өзгөртүү
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() бүттү: {size_a} байт, автоматтык сунуш тилке {} байт",
    plan_chunk_size(size_a, 8)
  );

  // Тилкеленген CRC32 текшерүү менен көп булактык жүктүү: бузулган тилке автоматтык түрдө булакты алмаштырат, жылдык булак автоматтык түрдө жай булактан тапшырууну жулуп алып тартылууда шайкештешет
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() текшерүү жана аяктоо: {size_b} байт");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## Интерфейс түшүндүрмөсү

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

Өткүр параллелдүүлүк `CONC` (`8`) жана өткүр бир жолку убакыт чектөө `TIMEOUT` (`30с`) менен `url_li` дан `path` ка жүктөп, файлдын жалпы байт санын кайтарат.

### `Get`

Конструктор кирүү чекити `Get::new(url_li, path)`, ыраатташтырылган конфигурацияны колдойт:

- `.size(size: u64)`: Белгилүү файлдын жалпы байт санын ачык түрдө көрсөтүү, алыскы узундукту өздөштүрүүдөн өтүү.
- `.chunk_size(chunk_size: usize)`: Бир тилкенин байт санын көрсөтүү (`0` өткөрсө `Error::ChunkSize` кайтарат).
- `.conc(conc: usize)`: Параллел жүктүү корутсу санын көрсөтүү.
- `.timeout(timeout: Duration)`: Бир жолку буйрук жана окуу убакыт чектөөсүн көрсөтүү.
- `.verify<V2: Verify>(verify: V2)`: Текшерүүчү киргизүү; `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` жана `Arc<T>` үчүн иштелип берилген.
- `.run().await`: Жүктүүнү баштап `Result<u64>` кайтарат.

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` 0 негизги тилке номери, `data` ошол тилкенин байт кесиндиси, `true` кайтаруу текшерүү өткөнүн билдирет.

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

`MIN_CHUNK` (`64 KB`) жана `MAX_CHUNK` (`4 MB`) аралыгында 2нин даражасы тилке байт санын кайтарат.

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

Жыйын константасы `PART_EXT` (`".part"`) кошуп, үзгүлтүктөн улантуу убактылуу файл дарегин кайтарат.

### `Error` жана `Result`

Бирдиктүү кайтаруу түрү `Result<T> = std::result::Result<T, Error>`, ката enum варианттары: `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`.
