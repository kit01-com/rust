# msrcget

[compio](https://crates.io/crates/compio)ର ଏସିଙ୍କ୍ରୋନସ୍ କମ୍ପ୍ଲେସନ୍ ମଡେଲ୍ ଉପରେ ଆଧାରିତ ମଲ୍ଟି-ସୋର୍ସ ଚଂକ୍ HTTP/HTTPS ଡାଉନଲୋଡ୍ ଲାଇବ୍ରେରୀ, ଯାହା ସିଙ୍ଗଲ୍ ମିରର ରେଟ୍ ଲିମିଟେସନ୍, ଚଂକ୍ ଡାଟା କ୍ଷତି ଓ ଧୀର ନୋଡ୍ ଟେଲ୍-ଡ୍ରିଫ୍ ମସ୍ଲହାକୁ ସମାଧାନ କରେ।

### ପରୀକ୍ଷା ପଦ୍ଧତି

ମୂଲ୍ୟାଙ୍କନ କୋଡ୍ `examples/bench.rs` ରେ ଅବସ୍ଥିତ (ଚାଳନା: `cargo run --profile bench --example bench`):

- ବେସ୍‌ଲାଇନ୍ ପ୍ରସ୍ତୁତି: ସମୟ ଗଣନା ଆରମ୍ଭ ପୂର୍ବରୁ ଲକ୍ଷ୍ୟ ଫାଇଲ୍‌କୁ ଗୁଡ଼େ ଅଗ୍ରାବଧିକ ଡାଉନଲୋଡ୍ କରାଯାଏ, ବାଇଟ୍ ଲମ୍ବ ଯାଞ୍ଚ କରାଯାଏ ଓ ସମ୍ପୂର୍ଣ୍ଣ ପ୍ୟାକେଜ୍ ଓ ପ୍ରତ୍ୟେକ ଚଂକ୍‌ର CRC32 ମାନକ ମୂଲ୍ୟ ଗଣନା କରାଯାଏ; ଏହି ପର୍ଯ୍ୟାୟ ସମୟ ଗଣନାରେ ଅନ୍ତର୍ଭୁକ୍ତ ନୁହେଁ।
- ସମୟ ଶେଷକାଠି: ପ୍ରତ୍ୟେକ ଯୋଜନା ୩ ପ୍ରସ୍ଥର ଲଗାତାର ସ୍ୱାଧୀନ ଚାଳନା କରେ; ପ୍ରତ୍ୟେକ ପ୍ରସ୍ଥ ଆରମ୍ଭ ପୂର୍ବରୁ ଆଉଟ୍ପୁଟ୍ ଫାଇଲ୍ ଓ `.part` ଅନ୍ତରୀଣ ଫାଇଲ୍ ମୁଖ୍ଷିତ କରାଯାଏ; ସମୟ ଗଣନା ନେଟୱର୍କ ଅନୁରୋଧ ଆରମ୍ଭରୁ ଆରମ୍ଭ ଓ ଫାଇଲ୍ ଡିସ୍କ୍ରେ ଲେଖା ସମ୍ପୂର୍ଣ୍ଣ ହେବା ପର୍ଯ୍ୟନ୍ତ ଚାଲେ। `cyper`, `reqwest`, `ureq` ସମସ୍ତେ ସ୍ପଷ୍ଟ ଭାବେ `sync_data` ଡିସ୍କ୍ ଫ୍ଲସ୍ ଚାଳନା କରନ୍ତି; `msrcget` ର ମୋଟ ସମୟରେ ରିମୋଟ୍ ଲମ୍ବ ପ୍ରୋବ, ସ୍ପାର୍ସ ଫାଇଲ୍ ସୃଷ୍ଟି, ସମାନ୍ତରାଳ ଚଂକ୍ ଡାଉନଲୋଡ୍, `sync_data` ଡିସ୍କ୍ ଫ୍ଲସ୍, ଅନ୍ତେ ଅନୁପ୍ରଯୁକ୍ତ ମେଟାଡାଟା କ୍ଷୁଦ୍ରୀକରଣ ଓ ପରିମେଯାତ୍ମକ ପୁନଃନାମିକରଣ ପୂର୍ଣ୍ଣ ପ୍ରକ୍ରିୟା ଅନ୍ତର୍ଭୁକ୍ତ।
- ପ୍ରତିଦ୍ୱୟ ପ୍ରମାଣ: ପ୍ରତ୍ୟେକ ପ୍ରସ୍ଥରେ ସମୟ ଗଣନା ରୁକ୍ମାନ କରିବା ପରେ ଡିସ୍କ୍ରେ ଲେଖା ଫାଇଲ୍‌କୁ ପ୍ରବାହୀ ଭାବେ ପଢ଼ାଯାଏ, ଫାଇଲ୍ ବାଇଟ୍ ଲମ୍ବ ଓ ସମ୍ପୂର୍ଣ୍ଣ ପ୍ୟାକେଜ୍ CRC32 ପ୍ରମାଣିତ ହୁଏ; ପ୍ରମାଣ ପ୍ରକ୍ରିୟା ଡାଉନଲୋଡ୍ ସମୟରେ ଅନ୍ତର୍ଭୁକ୍ତ ନୁହେଁ।
- ଥ୍ରୁପୁଟ୍ ପରିବର୍ତ୍ତନ: ୩ ପ୍ରସ୍ଥର ସମୟର ମଧ୍ୟମାକ ମୂଲ୍ୟ ଗ୍ରହଣ କରି, `ଫାଇଲ୍ ବାଇଟ୍ ସଂଖ୍ୟା / 1048576 / ମଧ୍ୟମାକ ସେକେଣ୍ଡ୍` ଦ୍ୱାରା ଥ୍ରୁପୁଟ୍ ଗଣନା କରାଯାଏ (`1 MB = 1048576 ବାଇଟ୍`)।
- ସୋର୍ସ ବାଣ୍ଟନ ନୀତି: ମଲ୍ଟି-ସୋର୍ସ ଯୋଜନା (`msrcget`, `down`) ପରିସ୍ଥିତିରେ ସମସ୍ତ ୫ଟି ମିରର ପାର୍ଥିତ୍ୟ ପ୍ରଦାନ କରେ; ଏକକ-ସୋର୍ସ ଯୋଜନା (`cyper`, `reqwest`, `ureq`) ମଲ୍ଟି-ସୋର୍ସ ଚଂକିଂକୁ ସମର୍ଥନ କରେ ନାହିଁ, ଅନୁରୋଧ ଲିଷ୍ଟର ପ୍ରଥମ ମିରର ପାର୍ଥିତ୍ୟ ବ୍ୟବହାର କରେ।

## ଖାସ୍ତଗୁଣ

- ଚଂକ୍‌ଭିତ୍ତିକ ପ୍ରମାଣ ଓ ଫେଲ୍‌ଓଭର: ପ୍ରତିଦ୍ୱୟକର୍ତ୍ତା `Verify` ପ୍ରମାଣ ଅନ୍ତରଘଟନ ପ୍ରଦାନ କରି ପ୍ରତ୍ୟେକ ଚଂକ୍ ପ୍ରମାଣିତ କରେ; ପ୍ରମାଣ ବିଫଳ କିମ୍ବା ନେଟୱର୍କ ଅନୁରୋଧ ବିଫଳ ହେଲେ, ସ୍ୱୟଂଚାଳିତ ଭାବେ ଅଗ୍ରାବଧିକ ଅପ୍ରୟୁକ୍ତ ମିରର ସୋର୍ସକୁ ପରିବର୍ତ୍ତନ କରି ପୁନଃଚେଷ୍ଟା କରାଯାଏ; ସମସ୍ତ ସୋର୍ସ ପର୍ଯ୍ୟାପ୍ତ ହେଲେ ବିଫଳ ହେଲେ `Error::Exhausted` ପ୍ରତିଗସ୍ତ ହୁଏ।
- ସ୍ପାର୍ସ ଫାଇଲ୍ ଓ ଅବରୋଧିତ ପୁନରୁଚାଳନା: ଫାଇଲ୍ ମୋଟ ଲମ୍ବ ଅନୁସାରେ ପୂର୍ବରୁ ସ୍ପାର୍ସ `.part` ଅନ୍ତରୀଣ ଫାଇଲ୍ ସୃଷ୍ଟି କରାଯାଏ ଓ ଫାଇଲ୍ ଲକ୍ ଲଗାଯାଏ (ଲକ୍ ସଂଘର୍ଷରେ `Error::Locked` ପ୍ରତିଗସ୍ତ)। ଫାଇଲ୍ ଶେଷରେ ଦ୍ୱି-ସ୍ଲଟ୍ ପିଙ୍ଗ୍‌ପଙ୍ଗ୍ CRC32 ବିଟମ୍ୟାପ୍ ଲେଖାଯାଏ ଯାହା ସମ୍ପୂର୍ଣ୍ଣ ଚଂକ୍ ସ୍ଥାୟୀକରଣ କରେ; ଅବରୋଧିତ ପରେ ପୁନଃଚାଳନାରେ ସ୍ୱୟଂଚାଳିତ ଭାବେ ଅବରୋଧିତ ସ୍ଥାନରୁ ନୂତନ ଆରମ୍ଭ, ସମସ୍ତ ସମ୍ପୂର୍ଣ୍ଣ ହେଲେ ଅନ୍ତେ ଅନୁପ୍ରଯୁକ୍ତ ମେଟାଡାଟା କ୍ଷୁଦ୍ରୀକରଣ ଓ ପରିମେଯାତ୍ମକ ପୁନଃନାମିକରଣ କରି ଲକ୍ଷ୍ୟ ଫାଇଲ୍ ସୃଷ୍ଟି କରେ।
- ଦ୍ୱିଖଣ୍ଡକ ତାସ୍କ ଷ୍ଟେଲିଂ: ନିଜେ ଅଞ୍ଚଳର ଡାଉନଲୋଡ୍ ପ୍ରଥମେ ସମ୍ପୂର୍ଣ୍ଣ କରିଥିବା ସୋର୍ସ ବାକି ସବୁତମ ଲମ୍ବ ଅସମ୍ପୂର୍ଣ୍ଣ ଅଞ୍ଚଳକୁ ସମାନ ଦ୍ୱିଭାଗରେ କାଟି ପର ଅଧା ଅଂଶ ଗ୍ରହଣ କରେ, ଫଳରେ ପ୍ରତ୍ୟେକ ମିରର ସୋର୍ସର ଲୋଡ୍ ସମତୁଲ୍ୟ ହୁଏ।
- ଅନ୍ତେ ଟ୍ରେଲ୍ ମଲ୍ଟି-ପାଥ୍ ରେସ୍: ଯେତେବେଳେ ମକ୍ତ କୋରୋଟିନ୍ ସଂଖ୍ୟା ବାକି ଅସମ୍ପୂର୍ଣ୍ଣ ଚଂକ୍ ସଂଖ୍ୟାଠାରୁ ଅଧିକ ହୁଏ, ସେହି ଅଗ୍ରାବଧିକ ଅପ୍ରୟୁକ୍ତ ଚଂକ୍‌କୁ ପୂର୍ବରୁ ପ୍ରୟୁକ୍ତ ନଥିବା ମିରର ସୋର୍ସକୁ ଅତିରିକ୍ତ ଅନୁରୋଧ ପ୍ରଦାନ କରାଯାଏ; ପ୍ରଥମ ପ୍ରମାଣିତ ଡାଟା ଡିସ୍କ୍ରେ ଲେଖା ହେବା ପରେ ସେହି ଚଂକ୍‌ର ଅନ୍ୟ ସମସ୍ତ ଅନୁରୋଧ ପ୍ରତିରୋଧିତ ହୁଏ।
- ସ୍ୱୟଂଚାଳିତ ଚଂକ୍ ଯୋଜନା: ଫାଇଲ୍ ମୋଟ ଲମ୍ବ ଓ ସମାନ୍ତରାଳ ସଂଖ୍ୟା ଅନୁସାରେ ଚଂକ୍ ସାଇଜ୍ ଯୋଜନା କରାଯାଏ; ଅବରୋଧିତ ଥିବା `.part` ଫାଇଲ୍ ପୁନରୁଚାଳନା ସମୟରେ ସେଥିରେ ରେକର୍ଡ୍ ଚଂକ୍ ସାଇଜ୍ ସ୍ୱୟଂଚାଳିତ ଭାବେ ବ୍ୟବହୃତ ହୁଏ।
- କନେକ୍ସନ୍ ପୁନରୁପଯୋଗ ଓ ପ୍ରୋଟୋକଲ୍ ସମର୍ଥନ: ସମାନ ସୋର୍ସର HTTP/1.1 ଲଙ୍ଗ-କନେକ୍ସନ୍ ପୁଣି ବ୍ୟବହାର ପାଇଁ ଅନ୍ତର୍ନିହିତ କନେକ୍ସନ୍ ପୁଲ୍, ଚଂକ୍ଡ ଟ୍ରାନ୍ସଫର ଏନକୋଡିଂ, HTTPS ([rustls](https://crates.io/crates/rustls)), `301`/`302`/`303`/`307`/`308` କ୍ରସ୍-ପାଥ୍ ଓ କ୍ରସ୍-ସୋର୍ସ ରିଡାଇରେକ୍ଟ ଓ ଟାଇମ୍ଆଉଟ୍ ନିୟନ୍ତ୍ରଣ ସମର୍ଥିତ।

## ବ୍ୟବହାର ପ୍ରଦର୍ଶନ

ଉଦାହରଣ କୋଡ୍ `examples/basic.rs` ରେ ଅବସ୍ଥିତ (ଚାଳନା: `cargo run --example basic`):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// CRC32 ଉପରେ ଆଧାରିତ ଚଂକ୍‌ଭିତ୍ତିକ ପ୍ରମାଣକ
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // ସୋର୍ସ 0 ର ପ୍ରଥମ ଚଂକ୍ କ୍ଷତିଗ୍ରସ୍ଟ ଡାଟା ପ୍ରତିଗସ୍ତ, ସୋର୍ସ 1 ଦ୍ରୁତ ଓ ସାଧାରଣ, ସୋର୍ସ 2 ଉଚ୍ଚ ବିଳମ୍ବ ଧୀର ନୋଡ୍
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // ଡିଫଲ୍ଟ ମଲ୍ଟି-ସୋର୍ସ ସମାନ୍ତରାଳ ଡାଉନଲୋଡ୍: ସ୍ୱୟଂଚାଳିତ ଚଂକ୍ ସାଇଜ୍ ଯୋଜନା, ସ୍ପାର୍ସ .part ଲେଖା ପରେ କ୍ଷୁଦ୍ରୀକରଣ ଓ ପୁନଃନାମିକରଣ
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // ଚଂକ୍‌ଭିତ୍ତିକ CRC32 ପ୍ରମାଣ ସହ ମଲ୍ଟି-ସୋର୍ସ ଡାଉନଲୋଡ୍: କ୍ଷତିଗ୍ରସ୍ଟ ଚଂକ୍ ସ୍ୱୟଂଚାଳିତ ସୋର୍ସ ପରିବର୍ତ୍ତନ, ଦ୍ରୁତ ସୋର୍ସ ସ୍ୱୟଂଚାଳିତ ଷ୍ଟେଲିଂ ଓ ଅନ୍ତେ ଧୀର ସୋର୍ସ ସହ ରେସ୍
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## ଅନ୍ତରଘଟନ ବର୍ଣ୍ଣନା

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

ଡିଫଲ୍ଟ ସମାନ୍ତରାଳ ସଂଖ୍ୟା `CONC` (`8`) ଓ ଡିଫଲ୍ଟ ଏକକ ଅନୁରୋଧ ଟାଇମ୍ଆଉଟ୍ `TIMEOUT` (`30s`) ବ୍ୟବହାର କରି `url_li` ରୁ `path` କୁ ଡାଉନଲୋଡ୍ କରେ, ଫାଇଲ୍ ମୋଟ ବାଇଟ୍ ସଂଖ୍ୟା ପ୍ରତିଗସ୍ତ କରେ।

### `Get`

ବୁଲ୍ଡର ଅନ୍ତରଦ୍ୱାର `Get::new(url_li, path)`, ଶୃଙ୍ଖଳିତ କଂଫିଗୁରେସନ୍ ସମର୍ଥିତ:

- `.size(size: u64)`: ଜଣାଶୁଣା ଫାଇଲ୍ ମୋଟ ବାଇଟ୍ ସଂଖ୍ୟା ସ୍ପଷ୍ଟ ଭାବେ ନିର୍ଦ୍ଦେଶନା, ରିମୋଟ୍ ଲମ୍ବ ପ୍ରୋବ ପ୍ରତିରୋଧନ।
- `.chunk_size(chunk_size: usize)`: ପ୍ରତ୍ୟେକ ଚଂକ୍‌ର ବାଇଟ୍ ସଂଖ୍ୟା ନିର୍ଦ୍ଦେଶନା (`0` ପ୍ରଦାନ କଲେ `Error::ChunkSize` ପ୍ରତିଗସ୍ତ)।
- `.conc(conc: usize)`: ସମାନ୍ତରାଳ ଡାଉନଲୋଡ୍ କୋରୋଟିନ୍ ସଂଖ୍ୟା ନିର୍ଦ୍ଦେଶନା।
- `.timeout(timeout: Duration)`: ଏକକ ଅନୁରୋଧ ଓ ପାଠନ ଟାଇମ୍ଆଉଟ୍ ନିର୍ଦ୍ଦେଶନା।
- `.verify<V2: Verify>(verify: V2)`: ପ୍ରମାଣକ ଅନ୍ତର୍କ୍ରିୟ, `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` ଓ `Arc<T>` ପାଇଁ ପୂର୍ବରୁ ସମ୍ପୂର୍ଣ୍ଣ।
- `.run().await`: ଡାଉନଲୋଡ୍ ଆରମ୍ଭ କରି `Result<u64>` ପ୍ରତିଗସ୍ତ କରେ।

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` ହେଉଛି 0-ଆଧାରିତ ଚଂକ୍ ସଂକ୍ରମଣ ସଂଖ୍ୟା, `data` ସେହି ଚଂକ୍‌ର ବାଇଟ୍ ଛାଣା, `true` ପ୍ରତିଗସ୍ତ ହେଲେ ପ୍ରମାଣ ସଫଳ ବୋଞ୍ଜାଏ।

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

`MIN_CHUNK` (`64 KB`) ଓ `MAX_CHUNK` (`4 MB`) ମଧ୍ୟରେ ୨ ର ଘାତ ଅଭିନନ୍ଦିତ ଚଂକ୍ ବାଇଟ୍ ସାଇଜ୍ ପ୍ରତିଗସ୍ତ କରେ।

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

ସରଣାକ୍ଷେତ୍ର ସ୍ଥିରାଙ୍କ `PART_EXT` (`".part"`) ଯୋଡ଼ି, ଅବରୋଧିତ ପୁନରୁଚାଳନା ଅନ୍ତରୀଣ ଫାଇଲ୍ ପାର୍ଥିତ୍ୟ ପ୍ରତିଗସ୍ତ କରେ।

### `Error` ଓ `Result`

ସମିକ୍ଷିତ ପ୍ରତିଗସ୍ତ ପ୍ରକାର `Result<T> = std::result::Result<T, Error>`, ତ୍ରୁଟି ଏନମ୍ ଭେରିଏଣ୍ଟ୍ ଅନ୍ତର୍ଭୁକ୍ତ: `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`।
