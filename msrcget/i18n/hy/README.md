# msrcget

Բազմաարբանուտ բլոկային HTTP/HTTPS ներբեռնման հավաքածու՝ [compio](https://crates.io/crates/compio)-ի ասինխրոն ավարտման մոդելի հիման վրա, որը լուծում է մեկ արտապատյանի սահմանափակումների, բլոկային տվյալների վնասվածության և դանալար հանգույցների թափերի լարման խնդիրները։

## Կարգադրվածության գնահատում

[down](https://crates.io/crates/down), [cyper](https://crates.io/crates/cyper), [reqwest](https://crates.io/crates/reqwest) և [ureq](https://crates.io/crates/ureq)-ի ներբեռնման արտադրողականության համեմատություն հանրային HTTPS արտապատյանների պայմաններում՝

### Գործարկում 1. խառը. Հանրային բազմաարբանուտ արտապատյանների խառը ներբեռնում

Ներբեռնվում է Node.js v22.14.0 տարածման փաթեթը (`node-v22.14.0-linux-x64.tar.xz`, 28.5 ՄԲ), արտապատյանները հերթականությամբ՝ Թսինխու, USTC, Թույա ամպ, Թենսենտ ամպ, npmmirror (ներառյալ 302 արտապատյանների միջև թարգմանում)։

| Հավաքածու / Ծրագիր | Արտադրողականություն (ՄԲ/վ) |
| --- | ---: |
| msrcget (5 աղբյուր, 8 միաժամանակյա) | 13.9 |
| msrcget + CRC32 | 13.4 |
| down (5 աղբյուր) | 1.2 |
| cyper (մեկ աղբյուր) | 14.4 |
| reqwest (մեկ աղբյուր) | 14.4 |
| ureq (մեկ աղբյուր) | 14.3 |

### Գործարկում 2. խառը. Արագ ու դանալար աղբյուրների խառը ներբեռնում

Ներբեռնվում է Node.js v22.14.0 վերնագրերի փաթեթը (`node-v22.14.0-headers.tar.gz`, 8.4 ՄԲ), արտապատյանները հերթականությամբ՝ Ալի ամպ (մեկ կապի սահմանափակում), Թսինխու, Թույա ամպ, Թենսենտ ամպ, Node.js-ի զտական աղբյուր (սահմանների վերը դանալար հանգույց)։

### Ստուգման եղանակ

Գնահատման կոդը գտնվում է `examples/bench.rs`-ում (աշխատում `cargo run --profile bench --example bench`)՝

- Զրկանական պատրաստություն. ժամանակավորումից առաջ նախ ներբեռնվում է նպատակային ֆայլը մեկ անգամ, ստուգվում է բայթերի երկարությունը և հաշվարկվում ամբողջ փաթեթի և յուրաքանչյուր բլոկի CRC32 ցուցանիշները, այս փուլը չի մտնում ժամանակի մեջ։
- Ժամանակավորման սահմաններ. Յուրաքանչյուր ծրագիրը անընդհատ անկախ աշխատում է 3 անգամ, յուրաքանչյուր անգամից առաջ ջնջվում են արտաքնային ֆայլը և `.part` ժամանակավոր ֆայլը; մեկ անգամը ժամանակավորվում է ցանցային հարցման ուղարկումից մինչև ֆայլի գրումն ավարտվելը (`cyper`-ը, `reqwest`-ը, `ureq`-ը բոլորը զտական կատարում են `sync_data` ֆայլի գրումը; `msrcget`-ը ներառում է հեռավոր երկարության ճանաչում, ցրած ֆայլի ստեղծում, միաժամանակյա բլոկային ներբեռնում, `sync_data` գրում, չեզոք տվյալների կտրում և ատոմար անվանափոխում)։
- Արդյունքների ստուգում. Յուրաքանչյուր անգամի ժամանակավորումից հետևյալ ըստ հոսանքի կարդվում է գրված ֆայլը, ստուգվում են բայթերի երկարությունը և ամբողջ փաթեթի CRC32-ը, ստուգման գործընթացը չի մտնում ներբեռնման ժամանակի մեջ։
- Արտադրողականության հաշվարկ. Գրվում է 3 անգամի ժամանակների մեջնային արժեքը, արտադրողականությունը հաշվարկվում է `ֆայլի բայթերի թիվ / 1048576 / մեջնային վայրկյաններ` բանաձևով (`1 ՄԲ = 1048576 բայթ`)։
- Աղբյուրների բաշխման կանոններ. Բազմաարբանուտ ծրագրերը (`msrcget`, `down`) ստանում են գործարկման մեջ գտնվող բոլոր 5 արտապատյանների հասցեները; մեկարբանուտ ծրագրերը (`cyper`, `reqwest`, `ureq`) չեն աջակցում բազմաարբանուտ բլոկային ներբեռնում, հարցման ցուցակում օգտագործվում է 1-ին արտապատյանի հասցեն։

## Հատկանիշներ

- Բլոկ առ բլոկ ստուգում և խնդիրների փոխարինում. Կանչողը փոխանցում է `Verify` ստուգման փորձադարձը յուրաքանչյուր բլոկը ստուգելու համար; ստուգումը չանցնելիս կամ ցանցային հարցումը ձախողվելիս ավտոմատ փոխարինվում է մնացած չփորձարկված արտապատյանների ցանկի միջով, բոլոր աղբյուրների անցման դեպքում ձախողման ժամանակ վերադարձվում է `Error::Exhausted`։
- Ցրած ֆայլ և ընդհատումից շարունակում. Ըստ ֆայլի ընդհանուր երկարության նախագույն ստեղծվում է ցրած `.part` ժամանակավոր ֆայլ և ավելանում է ֆայլային փակիչ (փակիչների բախման դեպքում վերադարձվում է `Error::Locked`); ֆայլի ավարտին գրվում է կրկնակի միջուկային պինգ-պոնգ CRC32 քարտեզ՝ ավարտված բլոկները տևական ձևով պահպանելու համար, ընդհատումից հետևյալ վերագործարկման դեպքում ավտոմատ շարունակում է, բոլորի ավարտից հետևյալ կտրում է չեզոք տվյալները և ատոմար անվանափոխում է դեպի նպատակային ֆայլ։
- Կեսականի խնամակցության գրավում. Նախավեցի իր շրջանի ներբեռնումը ավարտած աղբյուրը մնացած ամենամեծ անավարտ շրջանը կեսերի բաժանում է և վերցնում է երկրորդ կեսը, հավասարեցնելով յուրաքանչյուր արտապատյանի բեռնվածությունը։
- Ավարտին բազմաճանապարհ մրաբաղդ. Երբ ազատ կորոցների թիվը ավելի մեծ է, քան մնացած անավարտ բլոկների թիվը, դեպի այն արտապատյաններ, որոնք դեռ չեն փորձարկել այդ բլոկը, ուղարձվում են լրացուցիչ հարցումներ; առաջին ստուգումից անցած տվյալների գրումից հետևյալ միանգամից չեղարկվում են նույն բլոկի մնացած հարցումները։
- Ավտոմատ բլոկավորման ծրագրավորում. Ըստ ֆայլի ընդհանուր երկարության և միաժամանակյա աշխատանքի թվի ծրագրավորվում է բլոկի չափը; գոյություն ունեցող `.part` ֆայլից շարունակելիս ավտոմատ օգտագործվում է նրա մեջ գրված բլոկի չափը։
- Կապերի փոխադրում և մեթոդների աջակցություն. Ներքին նույն աղբյուրի կապերի բաշինք՝ HTTP/1.1 երկար կապերի փոխադրմամբ, աջակցություն բլոկային փոխադրման խեղդակմանը, HTTPS-ին ([rustls](https://crates.io/crates/rustls)), `301`/`302`/`303`/`307`/`308` ճանապարհների և աղբյուրների միջև թարգմանումներին և ժամանակի սահմանափակումներին։

## Օգտագործման ցուցադրություն

Օրինակի կոդը գտնվում է `examples/basic.rs`-ում (աշխատում `cargo run --example basic`)՝

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// CRC32-ի հիման վրա բլոկ առ բլոկ ստուգիչ
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // Աղբյուր 0-ի 1-ին բլոկը վերադարձնում է վնասված տվյալ, Աղբյուր 1-ը բարձր արագությամբ նորմալ, Աղբյուր 2-ը բարձր ուշադրությամբ դանալար հանգույց
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // Նախադիր բազմաարբանուտ միաժամանակյա ներբեռնում. ավտոմատ ծրագրավորում բլոկների չափ, ցրած .part գրում, կտրում և անվանափոխ
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // Բլոկ առ բլոկ CRC32 ստուգմամբ բազմաարբանուտ ներբեռնում. վնասված բլոկները ավտոմատ փոխարինվում են, արագ աղբյուրները ավտոմատ գրավում են և ավարտին մրաբաղդում են դանալար աղբյուրների հետ
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## Ինտերֆեյսի նկարագրություն

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

Օգտագործելով նախադիր միաժամանակյա աշխատանքի թիվը `CONC` (`8`) և նախադիր մեկանգամյա ժամանակի սահմանափակումը `TIMEOUT` (`30վ`), ներբեռնում է `url_li`-ը դեպի `path`, վերադարձնում է ֆայլի ընդհանուր բայթերի թիվը։

### `Get`

Շինարարի մուտք `Get::new(url_li, path)`, աջակցում է շղթայական կարգավորում.

- `.size(size: u64)`. Զտական նշելու դեպքում ֆայլի հայտնի ընդհանուր բայթերի թիվը, թողնել հեռավոր երկարության ճանաչումը։
- `.chunk_size(chunk_size: usize)`. Նշել մեկ բլոկի բայթերի թիվը (այսպես `0` փոխանցելիս վերադարձվում է `Error::ChunkSize`)։
- `.conc(conc: usize)`. Նշել միաժամանակյա ներբեռնման կորոցների թիվը։
- `.timeout(timeout: Duration)`. Նշել մեկանգամյա հարցման և ընթերցման ժամանակի սահմանափակումը։
- `.verify<V2: Verify>(verify: V2)`. Կարգադրել ստուգիչ, գրված է `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` և `Arc<T>` համար։
- `.run().await`. Սկսել ներբեռնումը և վերադարձնել `Result<u64>`։

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx`-ը 0-ից սկսվող բլոկի հաջորդական թիվն է, `data`-ն այդ բլոկի բայթերի հատվածն է, `true` վերադարձը նշանակում է ստուգման անցումը։

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

Վերադարձնում է 2-ի աստիճան բլոկային բայթերի թիվ `MIN_CHUNK` (`64 KB`) և `MAX_CHUNK` (`4 ՄԲ`) միջև։

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

Հավելում է վերջնահատակային հաստատունը `PART_EXT` (`".part"`), վերադարձնում է ընդհատումից շարունակման ժամանակավոր ֆայլի ճանապարհը։

### `Error` և `Result`

Կարգադրված վերադարձման տեսակ `Result<T> = std::result::Result<T, Error>`, սխալների անույլ ձևափոխությունները ներառում են՝ `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`։
