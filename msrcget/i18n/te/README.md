# msrcget

[compio](https://crates.io/crates/compio) అసింక్ కంప్లీషన్ మోడల్‌పై ఆధారంగా ఉన్న మల్టీ-సోర్స్ చంక్‌డ్ HTTP/HTTPS డౌన్‌లోడ్ లైబ్రరీ, ఏక మిరర్ రేట్-లిమిటింగ్, చంక్ డేటా దురవకాశం మరియు మందగమ నోడ్ టెయిలింగ్ సమస్యలను పరిష్కరించడానికి ఉపయోగించబడుతుంది.

## పనితన మూల్యాంకనం

[down](https://crates.io/crates/down), [cyper](https://crates.io/crates/cyper), [reqwest](https://crates.io/crates/reqwest) మరియు [ureq](https://crates.io/crates/ureq) పబ్లిక్ నెట్వర్క్ HTTPS మిరర్ సోర్స్‌లలో డౌన్‌లోడ్ థ్రూ‌ప్యూట్ పోలిక:

### సన్నివేశం 1: బహుళ పబ్లిక్ మిరర్ ఛానల్ డౌన్‌లోడ్:

Node.js v22.14.0 రిలీజ్ ప్యాకేజ్ డౌన్‌లోడ్ (`node-v22.14.0-linux-x64.tar.xz`, 28.5 MB), మిరర్ సీక్వెన్స్: Tsinghua, USTC, Huawei Cloud, Tencent Cloud, npmmirror (302 క్రాస్-సోర్స్ రీడైరెక్ట్‌తో సహా).

### టెస్టింగ్ పద్ధతి

బెంచ్మార్క్ కోడ్ `examples/bench.rs` లో ఉంది (`cargo run --profile bench --example bench` అమల్‌లో):

- బేస్‌లైన్ ప్రేపరేషన్: టైమింగ్ ముందు టార్గెట్ ఫైల్‌ను ముందే డౌన్‌లోడ్ చేసి, బైట్ పొడవు ధృవీకరించి, పూర్తి ప్యాకేజ్ మరియు ప్రతి చంక్‌లకు CRC32 బేస్‌లైన్ విలువలను గణించండి; ఈ దశ టైమింగ్‌లో భాగం కాదు.
- టైమింగ్ బౌండరీ: ప్రతి సోల్యూషన్ 3 వార్లు అంధాపంధంగా ధృవీకరించబడుతుంది, ప్రతి వారల ముందు అవుట్‌పుట్ ఫైల్ & `.part` టెంపరరీ ఫైల్‌ను తొలగించాలి; ప్రతి వార యాబ్జెక్ట్ నెట్వర్క్ రిక్వెస్ట్ ప్రారంభం నుండి టైమర్ మొదలుపెట్టి, ఫైల్ డిస్క్‌పై పూర్తిగా రాయబడే వరకు ఆపాలి (`cyper`, `reqwest`, `ureq` అన్నీ స్పష్టంగా `sync_data` ఫ్లష్‌ను అమల్‌లో చేస్తాయి; `msrcget` రిమోట్ లెంగ్త్ ప్రోబ్, స్పార్స్ ఫైల్ సృష్టి, కాన్కరెంట్ చంక్ డౌన్‌లోడ్, `sync_data` ఫ్లష్, టెయిల్ మెటాడేటా ట్రంకేషన్ & అటామిక్ రీనేమ్ - పూర్తి ప్రసెస్‌ను కలిగి ఉంది).
- అవుట్‌పుట్ వేరిఫికేషన్: ప్రతి వార టైమర్ ఆపిన తర్వాత ఫైల్‌ను స్ట్రీమింగ్ రీడ్ చేసి, బైట్ పొడవు & పూర్తి ప్యాకేజ్ CRC32 ధృవీకరించండి; వేరిఫికేషన్ ప్రసెస్ డౌన్‌లోడ్ టైమ్‌లో భాగం కాదు.
- థ్రూ‌ప్యూట్ కాంవర్షన్: 3 వారలలో మిడియన్ విలువ తీసుకుని, `ఫైల్ బైట్‌ల సంఖ్య / 1048576 / మిడియన్ సెకన్లు` ద్వారా థ్రూ‌ప్యూట్ గణించండి (`1 MB = 1048576 బైట్లు`).
- సోర్స్ డిస్ట్రిబ్యూషన్ రూల్స్: మల్టీ-సోర్స్ సోల్యూషన్లు (`msrcget`, `down`) సన్నివేశంలోని అన్ని 5 మిరర్ యాడ్రెస్‌లను పాస్ చేస్తాయి; ఏక-సోర్స్ సోల్యూషన్లు (`cyper`, `reqwest`, `ureq`) మల్టీ-సోర్స్ చంకింగ్‌ను సపోర్ట్ చేయవు, రిక్వెస్ట్ లిస్ట్‌లో మొదటి మిరర్ యాడ్రెస్‌ను ఉపయోగిస్తాయి.

## ఫీచర్లు

- చంక్-వైస్ వేరిఫికేషన్ & ఫెయిల్‌ఓవర్: యూజర్ `Verify` ఇంటర్ఫేస్ పాస్ చేసి ప్రతి చంక్‌ను ధృవీకరిస్తాడు; వేరిఫికేషన్ ఫెయిల్ అయితే లేదా నెట్వర్క్ రిక్వెస్ట్ ఫెయిల్ అయితే, ఆటోమేటిక్‌గా ఇంకా ట్రయ్ చేయని మిగిలిన మిరర్ సోర్స్‌కు స్విచ్ చేసి రీట్రయ్ చేస్తుంది, అన్ని సోర్స్‌లను ట్రవెర్స్ చేసి కూడా ఫెయిల్ అయితే `Error::Exhausted` రిటర్న్ చేస్తుంది.
- స్పార్స్ ఫైల్ & రెజ్యూమ్: ఫైల్ మొత్తం పొడవు ప్రకారం ముందుగా స్పార్స్ `.part` టెంపరరీ ఫైల్ సృష్టించి ఫైల్ లాక్ చేస్తుంది (లాక్ కాన్ఫ్లిక్ట్ అయితే `Error::Locked` రిటర్న్); ఫైల్ చివరిలో డుయల్-స్లాట్ పింగ్-పాంగ్ CRC32 బిట్మ్యాప్ రాయడం ద్వారా పూర్తయిన చంక్‌లను పర్సిస్ట్ చేస్తుంది, ఇంటర్‌రప్ట్ తర్వాత రీస్టార్ట్‌లో ఆటోమేటిక్‌గా రెజ్యూమ్ చేస్తుంది, అన్నీ పూర్తయిన తర్వాత టెయిల్ మెటాడేటా ట్రంక్ చేసి అటామిక్‌గా టార్గెట్ ఫైల్‌గా రీనేమ్ చేస్తుంది.
- బైనరీ టాస్క్ ష్టీలింగ్: తన సెగ్మెంట్ ముందుగా పూర్తి చేసుకున్న సోర్స్, మిగిలిన అపూర్తి పొడవైన సెగ్మెంట్‌ను రెండు పాళ్లుగా చీలి దూసి రెండవ భాగాన్ని టేక్‌ఓవర్ చేస్తుంది, ఇది అన్ని మిరర్ సోర్స్‌ల లోడ్‌ను బ్యాలెన్స్ చేస్తుంది.
- ఫైనల్ స్ప్రింట్ మల్టీ-పాత్ రేస్: ఐడిల్ కోరూటిన్లు మిగిలిన అపూర్తి చంక్‌ల కంటే ఎక్కువగా ఉన్నప్పుడు, ఆ చంక్‌ను ఇంకా ట్రయ్ చేయని మిరర్ సోర్స్‌లకు రెడ్‌ండెంట్ రిక్వెస్ట్లు డిస్పాచ్ చేస్తుంది; మొదటిగా వేరిఫై చేసిన డేటా డిస్క్‌పై రాయబడిన వెంటనే అదే చంక్‌కు చెందిన మిగిలిన రిక్వెస్ట్లను క్యాన్సిల్ చేస్తుంది.
- ఆటోమేటిక్ చంక్ ప్లనింగ్: ఫైల్ మొత్తం పొడవు & కాన్కరెన్సీ ప్రకారం చంక్ సైజ్ ప్లాన్ చేస్తుంది; ఇప్పటికే ఉన్న `.part` ఫైల్‌ను రెజ్యూమ్ చేసినప్పుడు ఆ ఫైల్‌లో నమోదైన చంక్ సైజ్‌ను ఆటోమేటిక్‌గా అనుసరిస్తుంది.
- కనెక్షన్ రీయూస్ & ప్రోటోకాల్ సపోర్ట్: ఇన్‌బిల్ట అదే సోర్స్ కనెక్షన్ పూల్ ద్వారా HTTP/1.1 లాంగ్-కనెక్షన్ రీయూస్, చంక్డ్ ట్రాన్స్‌ఫర్ ఎన్‌కోడింగ్, HTTPS ([rustls](https://crates.io/crates/rustls)), `301`/`302`/`303`/`307`/`308` క్రాస్-పాత్ & క్రాస్-సోర్స్ రీడైరెక్ట్లు మరియు టైమ్‌అవుట్ కంట్రోల్‌ను సపోర్ట్ చేస్తుంది.

## ఉపయోగ డెమో

ఉదాహరణ కోడ్ `examples/basic.rs` లో ఉంది (`cargo run --example basic` అమల్‌లో):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// CRC32 ఆధారిత చంక్-వైస్ వెరిఫయర్
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // సోర్స్ 0 తొలి చంక్‌లో దురవకాశపడిన డేటా, సోర్స్ 1 వేగంగా సాధారణం, సోర్స్ 2 అధిక డిలే మందగమ నోడ్
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // డిఫాల్ట్ మల్టీ-సోర్స్ కాన్కరెంట్ డౌన్‌లోడ్: ఆటోమేటిక్ చంక్ సైజ్ ప్లనింగ్, స్పార్స్ .part రాయడం తర్వాత ట్రంక్‌పేట్ & రీనేమ్
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // చంక్-వైస్ CRC32 వేరిఫికేషన్‌తో మల్టీ-సోర్స్ డౌన్‌లోడ్: దురవకాశ చంక్‌లలో ఆటోమేటిక్ సోర్స్ స్విచ్, వేగవంతమైన సోర్స్‌లు ఆటోమేటిక్ టాస్క్ ష్టీలింగ్ & ఫైనల్ స్ప్రింట్‌లో మందగమ సోర్స్‌లతో పోటీ
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## ఇంటర్ఫేస్ వివరణ

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

డిఫాల్ట్ కాన్కరెన్సీ `CONC` (`8`) & డిఫాల్ట్ టైమ్‌అవుట్ `TIMEOUT` (`30s`) తో `url_li` నుండి `path` కు డౌన్‌లోడ్ చేసి, ఫైల్ మొత్తం బైట్‌లను రిటర్న్ చేస్తుంది.

### `Get`

బీల్డర్ ఎంట్రిపాయింట్ `Get::new(url_li, path)`, చైన్డ్ కాన్ఫిగరేషన్‌ను సపోర్ట్ చేస్తుంది:

- `.size(size: u64)`: ముందే తెలుసుకున్న ఫైల్ మొత్తం బైట్‌లను స్పష్టంగా సెట్ చేసి, రిమోట్ లెంగ్త్ ప్రోబ్ ను స్కిప్ చేస్తుంది.
- `.chunk_size(chunk_size: usize)`: సింగిల్ చంక్ బైట్‌లను సెట్ చేస్తుంది (`0` పాస్ చేస్తే `Error::ChunkSize` రిటర్న్).
- `.conc(conc: usize)`: కాన్కరెంట్ డౌన్‌లోడ్ కోరూటిన్ల సంఖ్యను సెట్ చేస్తుంది.
- `.timeout(timeout: Duration)`: సింగిల్ రిక్వెస్ట్ & రీడ్ టైమ్‌అవుట్‌ను సెట్ చేస్తుంది.
- `.verify<V2: Verify>(verify: V2)`: వెరిఫయర్‌ను ఇంజెక్ట్ చేస్తుంది, `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` & `Arc<T>` కోసం ఇప్పటికే ఇంప్లెమెంట్ చేయబడింది.
- `.run().await`: డౌన్‌లోడ్ ప్రారంభించి `Result<u64>` రిటర్న్ చేస్తుంది.

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` అనేది 0-బేస్డ్ చంక్ ఇండెక్స్, `data` అనేది ఆ చంక్ బైట్ స్లాయిస్, `true` రిటర్న్ చేస్తే వేరిఫికేషన్ పాస్ అని సూచిస్తుంది.

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

`MIN_CHUNK` (`64 KB`) నుండి `MAX_CHUNK` (`4 MB`) వరకు 2 యొక్క పవర్ చంక్ బైట్‌లను రిటర్న్ చేస్తుంది.

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

సఫిక్స్ కాన్స్టంట్ `PART_EXT` (`".part"`) ను కలిపి, రెజ్యూమ్ టెంపరరీ ఫైల్ పాత్‌ను రిటర్న్ చేస్తుంది.

### `Error` & `Result`

యూనిఫైడ్ రిటర్న్ టైప్ `Result<T> = std::result::Result<T, Error>`, ఎర్రర్ ఎన్యూమ్ వేరియంట్లు: `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`.
