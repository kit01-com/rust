# msrcget

Многакрынічнае разбітнае HTTP/HTTPS-загружанне на аснове асіхронай мадэлі завяршэння [compio](https://crates.io/crates/compio), створанае для вырашэння праблем абмежавання хуткасці аднаго зеркала, пашкоджання даных разбітак і затрымкі з-за павольных вузлоў у канцы загружання.

## Вынікі вымярэнняў пераўтварнасці

Параўнанне прапускной здольнасці загружання з публічных HTTPS-зеркал для [down](https://crates.io/crates/down), [cyper](https://crates.io/crates/cyper), [reqwest](https://crates.io/crates/reqwest) і [ureq](https://crates.io/crates/ureq):

### Сцэнар 1: аб'яднанае загружанне з некалькіх публічных зеркал

Загружанне распаўсюджвальнага пакета Node.js v22.14.0 (`node-v22.14.0-linux-x64.tar.xz`, 28,5 МБ), зеркалы ў парадку: Цінхуа, USTC, Huawei Cloud, Tencent Cloud, npmmirror (з перанакіраваннем 302 паміж рознымі крыніцамі).

| Бібліятэка / рашэнне | Прапускная здольнасць (МБ/с) |
| --- | ---: |
| msrcget (5 крыніц, 8 парал.) | 13,9 |
| msrcget + CRC32 | 13,4 |
| down (5 крыніц) | 1,2 |
| cyper (адно зеркало) | 14,4 |
| reqwest (адно зеркало) | 14,4 |
| ureq (адно зеркало) | 14,3 |

### Сцэнар 2: загружанне з сумесі хуткіх і павольных крыніц

Загружанне пакета загалоўных файлаў Node.js v22.14.0 (`node-v22.14.0-headers.tar.gz`, 8,4 МБ), зеркалы ў парадку: Alibaba Cloud (абмежаванне хуткасці на адно злучэнне), Цінхуа, Huawei Cloud, Tencent Cloud, афіцыйнае зеркало Node.js (пагранны павольны вузел).

| Бібліятэка / рашэнне | Прапускная здольнасць (МБ/с) |
| --- | ---: |
| msrcget (5 крыніц, 8 парал.) | 13,5 |
| msrcget + CRC32 | 13,0 |

### Метад тэставання

Код вымярэнняў знаходзіцца ў `examples/bench.rs` (выканаць `cargo run --profile bench --example bench`):

- Падрыхтоўка базавых значэнняў: перад пачаткам вымярэння часу прадвыгрузіць мэту файл адзін раз, праверыць даўжыню ў байтах і вылічыць базавыя значэнні CRC32 для ўсяго файла і кожнай разбіткі; гэты этап не ўлічваецца ў затратах часу.
- Межы вымярэння часу: кожнае рашэнне выконваецца 3 разы паспільку незалежна; перад пачаткам кожнага раунда выдаляюцца выніковы файл і часовы файл `.part`; вымярэнне пачынаецца з моманту адпраўкі сеткавага запыту і заканчваецца пасля поўнага запісу файла на дыск (`cyper`, `reqwest`, `ureq` яўна выконваюць `sync_data` для прымусовага запісу; `msrcget` уключае прасоўванне далёкай даўжыні, стварэнне рэдкага файла, паралельнае разбітнае загружанне, `sync_data` для запісу, адрэзванне канцавых метаданых і атамарнае перайменаванне).
- Праверка вынікаў: пасля заканчэння вымярэння часу кожнага раунда запісаны файл чытаецца паточна, праверваецца даўжыня ў байтах і CRC32 ўсяго файла; працэс праверкі не ўлічваецца ў часе загружання.
- Пераўтварэнне прапускной здольнасці: брацца мядыяна часу 3 раундаў, прапускная здольнасць вылічваецца як `байты файла / 1048576 / мядыяна ў сек` (`1 МБ = 1048576 байтаў`).
- Правіла размеркавання крыніц: многіх крыніц (`msrcget`, `down`) атрымліваюць усе 5 адрасаў зеркал у сцэнары; адной крыніцы (`cyper`, `reqwest`, `ureq`) не падтрымліваюць разбіткі па крыніцах, выкарыстоўваецца 1-ы адрас зеркала са спісу запытаў.

## Асаблівасці

- Пацэлкавая праверка і пераключэнне памылкі: выклікальны бок перадае інтэрфейс `Verify` для праверкі кожнай разбіткі; пры няўдалай праверцы або няўдалым сетковым запыце аўтаматычна пераключаецца на астатнія непасведчаныя зеркалы для паўтораў; калі ўсе зеркалы вычарпаны і памылка захоўваецца, вяртаецца `Error::Exhausted`.
- Рэдкі файл і працяг загружання з перапынення: па агульнай даўжыні файла прадварыста ствараецца рэдкі часовы файл `.part` з файлавым замкам (конфлікт замку вяртае `Error::Locked`); у канцы файла запісваецца двухслатавы ping-pong CRC32-бітрама для персыстэматызацыі выкананых разбітак, пасля перапынення і перазапуску загружанне аўтаматычна працягваецца, пасля поўнага завяршэння адрэзаецца канцавыя метаданых і атамарна перайменноўваецца ў мэту файл.
- Двайістае крадзеж задач: зеркало, якое першым завершыла загружанне свайго інтэрвалу, папалавіце найбольшы нязавяршаны інтэрвал і прымае другую палову, выраўноўваючы нагрузку паміж зеркамі.
- Фінальная многіх шляхоў гонка: калі колькасць адчульных карэнтаў перавышае колькасць нязавяршаных разбітак, рассылаюцца лішнія запыты на зеркалы, якія яшчэ не прабавалі гэтую разбітку; першыя даныя, што праходзяць праверку, неадкладна запісваюцца на дыск, скасоўваючы астатнія запыты для той жа разбіткі.
- Аўтаматычнае плянаванне разбітак: па агульнай даўжыні файла і колькасці паралельнасці вызначаецца памер разбіткі; пры працягу наяўнага файла `.part` аўтаматычна выкарыстоўваецца запісаны ў ім памер разбіткі.
- Повторнае выкарыстанне злучэнняў і падтрымка пратаколаў: убудаваны пул злучэнняў аднаго зеркала повторно выкарыстоўвае перстыстныя злучэнні HTTP/1.1, падтрымлівае разбітнае кодаванне перадачы, HTTPS ([rustls](https://crates.io/crates/rustls)), перанакіраванні `301`/`302`/`303`/`307`/`308` паміж рознымі шляхамі і крыніцамі і кіраванне таймаўтамі.

## Дэманстрацыя выкарыстання

Прыклад код знаходзіцца ў `examples/basic.rs` (выканаць `cargo run --example basic`):

```rust
mod mock;

use std::{
  env::temp_dir,
  fs::{metadata, remove_file},
  sync::Arc,
  time::Duration,
};

use crc32fast::Hasher;
use mock::start_mirror;
use msrcget::{Get, Result, Verify, get, part_path, plan_chunk_size};

/// Пацэлкавы праверальнік на аснове CRC32
struct CrcVerify(Vec<u32>);

impl Verify for CrcVerify {
  fn verify(&self, idx: usize, data: &[u8]) -> bool {
    let mut hasher = Hasher::new();
    hasher.update(data);
    self.0.get(idx).copied() == Some(hasher.finalize())
  }
}

#[compio::main]
async fn main() -> Result<()> {
  let chunk_size = 64 * 1024;
  let data: Arc<[u8]> = (0usize..chunk_size * 8 + 512)
    .map(|i| (i.wrapping_mul(31) & 0xff) as u8)
    .collect::<Vec<_>>()
    .into();

  // Зеркало 0: першая разбітка вяртае пашкоджаныя даныя, зеркало 1: хуткае і нармальнае, зеркало 2: павольны вузел з вялікай затрымкай
  let u0 = start_mirror(Arc::clone(&data), chunk_size, Some(1), Duration::ZERO).await;
  let u1 = start_mirror(Arc::clone(&data), chunk_size, None, Duration::ZERO).await;
  let u2 = start_mirror(
    Arc::clone(&data),
    chunk_size,
    None,
    Duration::from_millis(200),
  )
  .await;

  let out_a = temp_dir().join("msrcget_demo_get.bin");
  let out_b = temp_dir().join("msrcget_demo_verify.bin");
  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  let _ = remove_file(part_path(&out_a));
  let _ = remove_file(part_path(&out_b));

  // Стандартнае паралельнае загружанне з некалькіх крыніц: аўтаматычнае плянаванне памеру разбітак, запіс рэдкага .part з наступным адрэзаннем і перайменнем
  let size_a = get([&u0, &u1, &u2], &out_a).await?;
  println!(
    "get() 完成: {size_a} 字节，自动建议分块 {} 字节",
    plan_chunk_size(size_a, 8)
  );

  // Загружанне з некалькіх крыніц з пацэлкай CRC32-праверкай: пашкоджаныя разбіткі аўтаматычна пераключаюць зеркало, хуткія зеркалы аўтаматычна крадуць задачы і ўдзельнічаюць у фінальнай гонцы з павольнымі
  let crc_li: Vec<u32> = data
    .chunks(chunk_size)
    .map(|chunk| {
      let mut h = Hasher::new();
      h.update(chunk);
      h.finalize()
    })
    .collect();

  let size_b = Get::new([&u0, &u1, &u2], &out_b)
    .chunk_size(chunk_size)
    .conc(4)
    .verify(CrcVerify(crc_li))
    .run()
    .await?;

  assert_eq!(metadata(&out_b)?.len(), size_b);
  println!("Get::verify() 校验并完成: {size_b} 字节");

  let _ = remove_file(&out_a);
  let _ = remove_file(&out_b);
  Ok(())
}
```

## Апісанне інтэрфейсаў

### `get`

`pub async fn get<I, S>(url_li: I, path: impl AsRef<Path>) -> Result<u64>`

Выкарыстоўвае стандартную колькасць паралельнасці `CONC` (`8`) і стандартны адзіночны таймаўт `TIMEOUT` (`30 с`) для загружання `url_li` ў `path`, вяртае агульную даўжыню файла ў байтах.

### `Get`

Уваходны пункт будвальніка `Get::new(url_li, path)`, падтрымлівае ланцужовае канфігураванне:

- `.size(size: u64)`: яўна задаць вядомую агульную даўжыню файла ў байтах, палічыць прасоўванне далёкай даўжыні.
- `.chunk_size(chunk_size: usize)`: задаць памер разбіткі ў байтах (пры перадачы `0` вяртаецца `Error::ChunkSize`).
- `.conc(conc: usize)`: задаць колькасць паралельных карэнтаў загружання.
- `.timeout(timeout: Duration)`: задаць таймаўт аднаго запыту і чытання.
- `.verify<V2: Verify>(verify: V2)`: устаўліць праверальнік, ужо рэалізаваны для `()`, `Fn(usize, &[u8]) -> bool`, `Rc<T>` і `Arc<T>`.
- `.run().await`: запусціць загружанне і вярнуць `Result<u64>`.

### `Verify`

`pub trait Verify { fn verify(&self, idx: usize, data: &[u8]) -> bool; }`

`idx` — нумар разбіткі (пачынаючы з 0), `data` — байтавы срез гэтае разбіткі, вяртанне `true` азначае паспяшную праверку.

### `plan_chunk_size`

`pub const fn plan_chunk_size(file_size: u64, conc: usize) -> usize`

Вяртае памер разбіткі ў байтах (ступень 2) паміж `MIN_CHUNK` (`64 КБ`) і `MAX_CHUNK` (`4 МБ`).

### `part_path`

`pub fn part_path(path: impl AsRef<Path>) -> PathBuf`

Прылучае канстанту суфіксу `PART_EXT` (`".part"`), вяртае шлях да часовага файла для працягу загружання.

### `Error` і `Result`

Адназначны тып вяртання `Result<T> = std::result::Result<T, Error>`, варыянты пераліку памылак уключаюць: `EmptySrc`, `ChunkSize`, `Url`, `Scheme`, `Io`, `Tls`, `Timeout`, `Redirect`, `Status`, `Proto`, `Probe`, `Locked`, `Exhausted { idx }`.
